## 二、挂起用例（P1，最优先）

**用例**：`tests/test_collection_batch_manager.py::test_run_batch_watchdog_kills_silent_engine_and_retries`（第 515–575 行）

**现象**：两次运行分别 4 分钟、5 分钟无任何进展，CPU/内存无变化，进程须手动终止。同文件相邻用例全部秒过，仅此一例卡死。

**测试设计**：构造一个"零输出、被 terminate 后才结束"的 `StalledProcess`（fake stdout 流），把看门狗阈值全部压到 0 / 0.01 秒，期望首轮被看门狗处决后自动补采第二轮成功。

**根因疑点**（代码定位，未经调试验证）：

1. 看门狗主循环在 `app/core/collection_batch_manager.py:736` 起：`while process.returncode is None: await asyncio.sleep(interval)`，靠 `time.monotonic()` 判静默超时后调 `process.terminate()`。阈值被 monkeypatch 为 0 后，首轮循环立即触发处决，逻辑上应很快走通。
2. 疑点一：**阈值被压到 0 让"正常完成路径"也被看门狗误杀**。首轮 `fake_run` 调用 `real_run` 后立即返回，但看门狗任务若未随进程退出而取消，可能继续跑第二轮/补采轮逻辑，与 `_run_batch` 的重入形成循环等待。
3. 疑点二：`StalledStream` 的读取端（测试文件第 95–110 行附近）依赖 `terminate()` 里的 `release()` 解锁；若 `real_run` 内部在读 stdout 的任务里还有 `await process.wait()` 之外的等待点（如 `stdout.read()` 返回的 TaskDialog），`release` 时序不对就会永久阻塞。
4. 疑点三：monkeypatch 替换的是 `manager._run_batch`，但 `real_run` 内部若经 `self._run_batch` 回调重入（测试注释明说了这一点），在 asyncio.run 的新事件循环里嵌套重入可能出现任务悬挂。

**建议排查路径**：单跑该用例 + `faulthandler.dump_traceback_later(30)` 或 py-spy 抓挂起时的线程栈，确定阻塞点在 watchdog 循环、stdout 读取还是重入回调；确认后修测试（或修 watchdog 的任务取消时序）。

**附带说明**：这是唯一会导致 CI 整体挂死的用例，建议在修复前先给它加 `@pytest.mark.timeout`（需装 pytest-timeout）或临时 skip，避免阻塞全量回归。

## 四、静态扫描发现（本次不修，仅记录）

1. **异常吞没**：全项目无裸 `except:`，但 `except Exception` 共 170 处，其中约 15+ 处是静默 `pass`：
   - `backup.py:78/141/339`、`maintenance.py:74/92/102/112`、`config.py:216/236`、`collection_planner.py:39/77`、`data_migration.py:143/151`、`dedup.py:144`、`douyin_api.py:133` 等。
   - 风险：故障发生时无任何日志，出问题只能靠现象倒推（本次账号解析"卡死"排查就吃过这类亏）。
   - 建议：统一补最低限度的 `logger.debug("...: %s", error)`。
2. **f-string SQL**：`backup.py:60` 与 `backup.py:300` 的 `VACUUM INTO '{path}'` 直接拼接路径。SQLite 的 `VACUUM INTO` 本身不支持参数绑定，但路径含单引号（如用户自定义备份目录 `D:\It's\backup`）会直接语法错误。建议拼接前做单引号转义（`path.replace("'", "''")`）。`database.py:270-396` 数处 f-SQL 拼接的是内部表名/列名，风险低。
3. **环境注意**：本机若被注入 `PYTHONHOME`/`PYTHONPATH` 环境变量，venv 会直接崩溃（`SRE module mismatch`）。跑测试时需先清除这两个变量，已写入个人工作方式备忘。
4. **阻塞式 sleep**：`downloader.py:139`、`tray.py:131/169` 的 `time.sleep` 均在独立线程上下文，不影响主循环；`collection_batch_manager.py:625` 是限速用途，可接受。
