# 采集功能设计文档

- 日期: 2026-08-15
- 状态: 待审阅
- 范围: 批量采集、单作品采集、TTD 配置生成与进程管理

## 1. 背景

DoukHub 已有账号表、Cookie 池、采集页面和 TTD Web API 封装，但当前“整号采集”调用 `/douyin/account` 后只统计返回的作品数量，既不下载文件，也无法支撑数百账号的长时间任务。TTD 本身已经具备批量下载、下载记录去重、日期窗口增量、多线程下载和断点处理能力，DoukHub 不应重复实现这些内核功能。

本设计将职责调整为:

- DoukHub: 管理账号资产、批次策略、TTD 配置、任务状态和用户界面。
- TTD: 负责整号批量下载、文件归档、下载去重和增量请求。
- TTD Web API: 常驻,负责链接解析、账号资料和单作品元数据获取。

## 2. 目标

1. 支持数百账号的整号批量下载,任务在后台运行,关闭页面不中断。
2. DoukHub 每次只把本批次账号写入 TTD 的 `accounts_urls` / `accounts_urls_tiktok`。
3. 普通账号首次全量,后续根据 DoukHub 记录的上次成功采集日期生成 `earliest` 增量窗口。
4. 高产账号可使用固定日期窗口,例如最近 200 天。
5. 单作品下载由 DoukHub 调 TTD API 获取信息和下载地址后自行下载,保存位置和命名规则由用户控制。
6. 批量侧复用 TTD 的下载目录、下载记录和文件命名配置,不在 DoukHub 中复制下载内核。

非目标:

- 不建立全量作品元数据表。
- 不做作品级同步到飞书。
- 不显示账号内每个作品的下载进度。
- 不让 DoukHub 管理批量下载的文件命名和目录结构。
- 第一阶段不改造小红书采集链路。

## 3. 批量采集设计

### 3.1 账号筛选

用户在采集页选择:

- 评级筛选,例如 3 星及以上。
- 可选标签筛选。
- 可选指定账号。
- 采集模式: 全量、增量、固定窗口。

账号必须满足:

- 未软删除。
- 已启用。
- 平台为抖音或 TikTok。
- 已有 `sec_user_id`。

筛选结果按等级倒序排列。等级相同的账号按账号名称稳定排序。

### 3.2 TTD 配置生成

配置文件为 `TikTokDownloader/Volume/settings.json`。DoukHub 读取现有配置后只替换:

- `accounts_urls`
- `accounts_urls_tiktok`

其他字段全部原样保留。写入必须使用原子替换,避免半份配置被 TTD 读取。

抖音账号生成:

```json
{
  "mark": "DoukHub 账号名称",
  "url": "https://www.douyin.com/user/{sec_user_id}",
  "tab": "post",
  "earliest": "",
  "latest": "",
  "enable": true
}
```

TikTok 账号使用账号表中已有的主页链接;缺失主页链接的 TikTok 账号标记为“配置跳过”。

规则:

- `mark` 使用账号名称,作为人可读标识;账号唯一身份仍是 `sec_user_id`。
- `tab` 第一阶段固定为 `post`,即发布作品。
- `earliest` 留空表示全量。
- 具体日期必须写成 `YYYY/MM/DD`,这是 TTD 源码要求的格式。
- 数字窗口直接写天数,例如 `200` 表示基于当天往前 200 天。

### 3.3 增量策略

账号表新增字段:

- `last_collected_at`: 上次成功采集日期。
- `collect_window_days`: 可空。设置后该账号始终使用固定窗口。

生成 `earliest` 的规则:

1. 若账号设置了 `collect_window_days`,使用该天数。
2. 若是首次采集或用户明确选择全量,留空。
3. 否则使用 `last_collected_at - 1 天`,重叠一天防止边界作品漏采。

TTD 继续使用 `download_data` 和目标文件存在性判断跳过已下载作品。DoukHub 不写、不改、不清空 TTD 的 `download_data`。

批次结束后,只把已确认处理成功的账号的 `last_collected_at` 更新为批次开始日期。若批次取消或进程异常退出,同样只更新已确认成功的账号。

### 3.4 批量进程

TTD Web API 进程保持常驻。批量下载时,DoukHub 新启动一个 TTD 终端批量进程:

```text
准备配置
  → 启动 TTD 终端批量进程
  → TTD 读取 accounts_urls
  → TTD 获取作品列表并下载文件
  → DoukHub 捕获输出、解析账号进度
  → 进程退出后更新批次和账号状态
```

约束:

- 同一时间最多存在一个批量下载进程。
- 批量进程与 API 进程使用同一份代码和同一个工作目录。
- API 进程不做批量文件下载,避免两个进程写同一下载目录。
- 抖音和 TikTok 分开执行;如果同一批次包含两个平台,先跑完一个平台再跑另一个。
- 进程输出写入 DoukHub 管理的批次日志文件。

启动方式使用 DoukHub 拥有的 runner 脚本直接进入 TTD 终端批量功能,不依赖人工菜单输入,也不修改 TTD 源码。runner 以 TTD 目录为工作目录启动。

### 3.5 批次状态

新增两张表:

`collection_batches`

| 字段 | 说明 |
|------|------|
| id | 批次 ID |
| status | pending / running / cancelling / completed / failed / cancelled |
| filter_json | 评级、标签、指定账号等筛选快照 |
| platform | douyin / tiktok |
| process_pid | TTD 批量进程 PID |
| log_path | 批次日志路径 |
| started_at | 开始时间 |
| finished_at | 结束时间 |
| total_accounts | 账号总数 |
| success_accounts | 成功账号数 |
| failed_accounts | 失败账号数 |

`collection_batch_items`

| 字段 | 说明 |
|------|------|
| batch_id | 所属批次 |
| account_record_id | DoukHub 账号记录 |
| sec_user_id | 账号唯一身份 |
| account_name | 账号名称快照 |
| platform | 平台 |
| mark | 写入 TTD 的标识 |
| url | 写入 TTD 的主页链接 |
| earliest | 写入 TTD 的日期窗口 |
| status | pending / running / success / failed / skipped / cancelled |
| message | 错误或跳过原因 |
| started_at | 开始时间 |
| finished_at | 结束时间 |

进度解析以 TTD 输出中的账号序号和结果摘要为主。若无法精确判断单个账号成败,该项保持 `running`,批次结束时根据进程退出码和 TTD 汇总信息收敛状态;不猜测成功。

### 3.6 取消与重试

取消:

1. 用户点击取消,DoukHub 将批次标记为 cancelling。
2. 终止 TTD 批量进程。
3. 尚未开始的账号标记为 cancelled。
4. 已确认成功的账号保留结果并更新 `last_collected_at`。

重试:

- 批次内 `failed` 和 `cancelled` 的账号可重新生成一个新批次。
- 新批次沿用当前增量规则,不自动改为全量。
- 用户可对选中账号手动选择“重新全量”。

## 4. 单作品采集设计

### 4.1 元数据获取

用户粘贴一个或多个抖音 / TikTok 作品链接。DoukHub 调 TTD Web API:

- 抖音: `/douyin/detail`
- TikTok: `/tiktok/detail`

API 返回标题、作者、发布时间、作品类型、封面和下载地址。DoukHub 展示解析结果,用户确认后再下载。

### 4.2 文件下载

DoukHub 使用自己的 HTTP 下载器保存文件:

- 用户选择目标目录。
- 命名模板默认 `发布时间 作者 标题`,可调整。
- 文件名做 Windows 非法字符清理和长度截断。
- 视频保存为一个文件。
- 图集按序号生成多个文件。
- 下载使用临时文件,成功后原子移动到目标路径。

单作品下载不写 TTD 的 `download_data`,不参与整号归档去重。其语义是“灵活取件”,与 TTD 批量档案库分开。

## 5. 页面效果

### 5.1 批量采集

采集页展示:

- 筛选条件和预计账号数。
- 当前批次状态。
- 已运行时长。
- 当前处理到第几个账号。
- 成功、失败、跳过数量。
- 上次成功采集日期。
- 批次日志入口。
- 取消按钮。
- 失败重试入口。

页面刷新或关闭后任务继续运行,重新进入页面时恢复状态。

### 5.2 单作品采集

输入链接后显示:

- 识别到的平台和作品数。
- 每个作品的标题、作者、发布时间、类型。
- 保存目录选择。
- 命名模板。
- 下载状态和错误信息。

## 6. 错误处理

- TTD API 未运行: 批量任务开始前检查 API 健康;单作品解析直接返回可操作错误。
- TTD 批量进程已存在: 拒绝新批次并提示当前批次。
- 配置写入失败: 批次进入 failed,不启动进程。
- 主页链接缺失: 该账号标记 skipped,不阻塞其他账号。
    - 抖音账号可用 `sec_user_id` 生成稳定主页链接。
    - TikTok 账号目前必须已有主页链接。
- TTD 进程非零退出: 批次 failed,已确认成功项保留成功状态。
- 日志解析失败: 不影响文件下载,只影响页面细粒度进度。
- 单作品下载中断: 删除临时文件,该项标记 failed,可重试。

## 7. 测试计划

单元测试:

- 账号筛选和排序。
- `settings.json` 原子更新且保留无关字段。
- 抖音主页 URL 生成。
- `earliest` 日期格式和重叠一天逻辑。
- 固定窗口天数生成。
- 批次与账号条目状态迁移。
- TTD 输出解析。
- 单作品文件名清理、图集编号和临时文件移动。

集成测试:

- 使用假 TTD 进程验证启动、日志捕获、取消和退出码处理。
- 使用假 API 响应验证单作品解析和下载。

手工验收:

1. 选 1 个小账号执行首次全量批量下载。
2. 再次执行同一账号,确认生成增量 `earliest` 且 TTD 跳过已下载文件。
3. 批量运行中刷新和关闭页面,确认任务继续。
4. 取消批量任务后重试失败账号。
5. 粘贴视频和图集链接,确认单作品下载到自定义目录。
