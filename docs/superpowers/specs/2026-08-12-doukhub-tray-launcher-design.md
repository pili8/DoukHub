# DoukHub 托盘启动方案设计文档

- 日期: 2026-08-12
- 状态: 待审阅
- 范围: 新增托盘启动程序 + 隐藏窗口 + 开发热重载

## 1. 背景与目标

DoukHub 当前通过 `start.bat` 启动:弹出一个黑窗口(cmd),运行 uvicorn 服务,用户需一直保持窗口打开、用 Ctrl+C 退出。用户处于**开发调试阶段**,希望启动体验像正常 App:

- 双击启动后**不显示黑窗口**,服务在后台运行
- 任务栏右下角出现**托盘图标**,通过图标菜单操作
- 改代码后**无需手动重启**(热重载)

现状:服务端 `run()` 使用 `uvicorn.run(..., reload=False)`(app/main.py 2358 行),改代码需重启;启动时已自动拉起 TikTokDownloader/XHS(未装则跳过)。

## 2. 设计目标

- 双击启动图标 → 后台运行 DoukHub 服务(无黑窗口)+ 托盘图标出现 + 浏览器自动弹出
- 托盘菜单:打开界面 / 重启服务(二级:只重启 DoukHub、重启全部含下载器)/ 退出
- 开发模式:热重载(reload=True),改代码自动重启,浏览器刷新生效
- 遵循 YAGNI:不做自动开机自启、不做打包成独立 exe(二期再说)

## 3. 交互设计

### 3.1 启动与托盘

- 用户双击 `DoukHub.bat`(或 `start.bat` 改造)
- 进程以**无窗口模式**运行(Windows 的 pythonw 机制),不显示黑窗口
- 服务在后台启动,托盘图标出现在任务栏右下角
- 服务就绪后自动打开浏览器访问 `http://127.0.0.1:2999`

### 3.2 托盘菜单结构

```
DoukHub 图标
├── 打开界面         → 浏览器打开 http://127.0.0.1:2999
├── 重启服务 ▸
│   ├── 只重启 DoukHub     → 停止并重启 DoukHub 进程
│   └── 重启全部(含下载器)  → 停止并重启 DoukHub + TikTokDownloader/XHS
└── 退出             → 停止服务 + 移除托盘图标 + 进程结束
```

- 左键单击托盘图标 = 打开界面(快捷)
- 右键单击 = 弹出菜单

## 4. 技术方案

### 4.1 组件构成

新增一个**托盘主程序**(如 `tray.py`),它负责:

1. 创建托盘图标(pystray 库)
2. 以子进程方式启动/停止整理服务(uvicorn,reload=True)
3. 响应用户菜单点击

分层逻辑:

```
tray.py (托盘主程序,常驻)
  ├── 启动/停止 DoukHub 服务子进程 (uvicorn reload=True)
  ├── 启动/停止 下载器服务 (复用现有 ServiceManager)
  └── 响应菜单: 打开浏览器 / 重启 / 退出
```

### 4.2 隐藏窗口

- 用 `pythonw.exe` 运行托盘主程序(pythonw 是 Windows 提供的"无控制台" Python,不弹黑窗口)
- DoukHub 服务作为子进程启动时,同样以无窗口方式(`CREATE_NO_WINDOW` 标志),避免黑窗口

### 4.3 开发热重载

- 服务子进程以 `uvicorn.run(app, reload=True)` 启动
- uvicorn 的 reload 机制:监控项目文件变化,检测到修改自动重启进程
- 子进程重启不影响托盘主程序,托盘图标常驻

### 4.4 服务重启逻辑

- **只重启 DoukHub**:停掉 uvicorn 子进程 → 重新启动(reload 模式)
- **重启全部**:停掉 uvicorn 子进程 + 停掉 TikTokDownloader/XHS 子进程 → 全部重新启动
- 复用现有 `ServiceManager`(app/services/downloader.py)管理下载器,托盘程序只负责"停"和"启"的编排

### 4.5 依赖

- 新增 `pystray`(创建系统托盘图标)+ `Pillow`(生成/加载图标图像)
- 图标素材:可复用 `TikTokDownloader/static/images/DouK-Downloader.ico`,或生成一个占位图标

## 5. 数据流

```
双击启动 → 托盘主程序(pythonw,无窗口)
  → 启动 uvicorn 子进程 (reload=True, 隐藏窗口)
  → 启动 TikTokDownloader/XHS (已有 auto_start_services 逻辑)
  → 托盘图标出现
  → 浏览器自动打开 127.0.0.1:2999
用户点"打开界面" → 调系统默认浏览器打开 URL
用户点"只重启" → 停 uvicorn 子进程 → 重启
用户点"重启全部" → 停 uvicorn + 下载器 → 全部重启
用户点"退出" → 停所有子进程 → 移除托盘图标 → 进程退出
```

## 6. 错误处理

- 端口 2999 被占用:托盘程序检测到后提示,或复用现有清理逻辑
- 服务启动失败:托盘一直显示图标,但可查看日志;菜单仍可用
- 下载器未安装:跳过(现有逻辑已处理)

## 7. 测试计划

- 手动验证:
  - 双击启动无黑窗口,托盘图标出现,浏览器自动打开
  - 左键单击 = 打开界面;右键 = 菜单
  - "只重启 DoukHub" 后服务重启、下载器保持
  - "重启全部" 后三者都重启
  - "退出" 后所有进程结束、托盘图标消失
  - 改代码后刷新浏览器即生效(热重载)
- 无自动化测试(托盘是 GUI/进程编排,以手动验证为主)

## 8. 范围外(YAGNI)

- 开机自动启动(随 Windows 启动)
- 打包成独立 exe(不需要 Python 环境)
- 托盘菜单显示服务状态/日志
- 更新检查
