# 设置页信息架构梳理（卡片盘点 + 归类方案）

> 2026-09-26 · 为设置页卡片重排做准备。先盘点、再归类、后原型。
> 范围：`app/templates/settings.html`，纯模板层重排，不动任何后端逻辑。
> 修订 v2：标签映射经代码查证属于采集（方案弹窗打标签），改归采集类；"底座"命名作废。

## 一、现状盘点：全部卡片清单

设置页现有 **4 个 Tab、7 张卡 + 1 个机柜视图**：

| # | 卡片 | 当前 Tab | 管什么（字段级） | 实际服务于 | 使用频率 |
|---|------|---------|-----------------|-----------|---------|
| 1 | 应用数据目录 | DoukHub配置 | 数据目录迁移、备份目录设置 | 程序自身（数据放哪、备份放哪） | 极低（装好基本不动） |
| 2 | 存储方案（机柜） | 存储方案 | 主/次方案落盘目录、文件名规则 | 采集（作品落盘到哪、叫什么名） | 高（常来改/看方案） |
| 3 | 内核服务 | 内核服务 | TTD/XHS 路径、端口、自启动、保活、一键更新 | 采集（采集引擎的运行前提） | 极低（配完不动） |
| 4 | 采集与 Cookie | 内核服务 | 并发账号数、Cookie 轮换模式、使用次数上限 | 采集（怎么采、多快采） | 中低（偶尔调参） |
| 5 | 云端配置 | 功能配置 | 飞书 App ID/Secret、表格 Token、三表 ID、轮询间隔、测试连接 | 云同步（飞书连接） | 中（初配 + 排障） |
| 6 | API 模式 | 功能配置 | 开关、API Key、接口列表与示例 | 对外接口（外部设备调用） | 极低 |
| 7 | 标签映射 | 功能配置 | 缩写=完整标签 映射表 | **采集**（给账号打标签时的选项与缩写展开；代码查证：`/api/tags/options` 供方案弹窗多选下拉使用） | 中低 |

### 现有分 Tab 的问题

1. **「功能配置」是个杂烩**——飞书、API、标签三件不相干的事挤在一个 Tab。
2. **采集相关散在 3 个 Tab**——存储方案（Tab2）、采集与 Cookie（Tab3）、标签映射（Tab4），找一样东西要想"它在哪"。
3. **「内核服务」名不副实**——Tab 里装着「采集与 Cookie」这张采集行为卡。
4. **Tab 按配置对象命名，不按用途**——"DoukHub配置 / 内核服务"是技术视角；用户想的是"我要改采集 / 我要弄飞书"。

## 二、归类方案

### 归类依据（三条原则，按优先级）

1. **按业务线分组**：卡片归入它实际服务的那条业务线（以代码实际用途为准，不凭卡片名字猜）。
2. **组内按使用频率排序**：常动的在上，配完不动的在下。
3. **低频系统项收拢在最后**：程序自身设置、对外接口这类"配完基本不看"的归一组垫底。

### 归类结果（三类）

| 类别 | 卡片（按组内顺序） | 归类依据 |
|------|------------------|---------|
| **采集** | 存储方案机柜 → 采集与 Cookie → 标签映射 → 内核服务 | 四张卡全为"把作品采下来"服务：落盘位置与命名 / 采集节奏与 Cookie / 账号打标签（方案弹窗的标签来源，代码查证）/ 采集引擎运行参数 |
| **云同步** | 云端配置 | 飞书连接的唯一入口；标签映射已查证不属于此（见盘点 #7） |
| **系统与接口** | 应用数据目录 → API 模式 | 程序自身的设置（数据、备份）+ 对外开放的调用口子，都是配一次然后忘掉的东西 |

### 落地为 Tab：4 Tab 收成 3 Tab

| 新 Tab | 内容 | 对应现状 |
|--------|------|---------|
| **① 采集**（默认） | 存储方案机柜 + 采集与 Cookie + 标签映射 + 内核服务 | 存储方案 Tab + 内核服务 Tab 合并，标签映射迁入 |
| **② 云同步** | 云端配置 | 功能配置 Tab 拆分（此 Tab 目前仅 1 卡，后续飞书功能扩展有去处） |
| **③ 系统与接口** | 应用数据目录 + API 模式 | DoukHub配置 Tab 改名 + API 迁入 |

**备选：保持 4 Tab**（改动更小）：DoukHub配置 → 采集与存储（存储+Cookie+标签+内核）→ 云同步（云端）→ 接口（API）。
不推荐的原因：「云同步」「接口」两个 Tab 都只剩 1 张卡，Tab 栏显得空。
