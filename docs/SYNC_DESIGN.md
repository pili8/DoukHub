# 飞书同步方案设计

本文档说明 DoukHub 与飞书多维表格的双向同步设计。包含两个方案：
- **方案 A**（当前 `main` 分支稳定版）：字段级单向同步
- **方案 B**（`feature/sync-v3-lww` 分支开发中）：基于时间戳的 LWW 真双向同步

---

## 📌 两个方案的对比

| 维度 | 方案 A（当前 main） | 方案 B（feature/sync-v3-lww） |
|---|---|---|
| **设计** | 字段级单向（按字段归属决定方向） | 真正的双向 LWW（最后修改时间胜出） |
| **冲突解决** | 字段归属固定（飞书赢/本地赢） | 比较两端修改时间，谁新谁赢 |
| **用户体验** | 在「错的端」修改会被覆盖 | 两端修改都有效 |
| **基础设施** | 无需额外字段 | 飞书表加「最后更新时间」+ 本地加 `local_updated_at` |
| **复杂度** | 低 | 中 |
| **稳定性** | 已稳定（v2.1.0-sync-a） | 开发中 |

---

## 🅰️ 方案 A：字段级单向同步

### 设计原则

每个业务字段固定归属一个「权威源」：
- **☁️ 飞书赢**：飞书是权威源，飞书 → 本地 单向同步
- **💻 本地赢**：DoukHub 是权威源，本地 → 飞书 单向同步
- **🔒 immutable**：创建后不变，不参与冲突解决
- **⚙️ sync_generated**：同步动作产生的字段（同步时间等）

**注意**：方案 A 不是真正的双向同步，而是「按字段划分的双向」——每个字段只能在一端修改有效。

### 已知限制

1. **不是真正的双向同步**：在错的端修改会被覆盖
   - 例：在本地数据管理页改「等级」→ 同步后会被飞书的值覆盖
   - 例：在飞书表改「粉丝数」→ 同步后会被本地的值覆盖
2. **多设备协作下删除会丢数据**：A 设备删除 + B 设备修改 → B 的修改丢失（删除优先 A 方案）
3. **飞书端重复业务键**：本地 UNIQUE 约束拒绝，标记 skipped_duplicate，需用户去飞书清理
4. **飞书批量删除 > 50%**：日常增量同步无法处理（比例保护），需用全盘同步

### 删除同步机制

- **飞书端删除**：直接按飞书删除按钮，下次同步时本地通过差集反推感知（依赖 `synced=1` 标记）
- **本地端删除**：DoukHub 内部软删除（`is_deleted=1` 墓碑），推送删除到飞书，飞书确认后清墓碑
- **三层安全保护**：
  - `synced=1` 过滤：本地新建未同步的不会被误删
  - 空结果保护：飞书返回 0 条直接跳过
  - 50% 比例保护：飞书返回数量 < 本地 50% 时跳过

## 🅱️ 方案 B：LWW 真双向同步（规划中）

### 设计目标

让真正需要双向的字段支持「两端都能改，谁后改谁赢」，解决方案 A 中用户在错的端修改无效的问题。

### 改动范围

只对**真正需要双向**的 6 个字段改为 LWW（最后修改时间胜出）：

| 字段 | 出现的表 | 为什么需要双向 |
|---|---|---|
| 等级 | 采集表 + 账号表 | 用户可能两端都改 |
| 标签 | 采集表 + 账号表 | 用户可能两端都改 |
| 备注 | 采集表 + 账号表 + Cookie表 | 用户可能两端都改 |
| 启用 | 账号表 + Cookie表 | 用户可能两端都改 |
| 采集类型 | 账号表 | 用户可能两端都改 |
| 状态 | Cookie表 | DoukHub 验证 + 用户手动改 |

其他字段保持单向（API 字段 DoukHub 是源、元数据不变）。

### 实施步骤

1. 数据库迁移：3 张表加 `local_updated_at DATETIME` 字段
2. 飞书表加「最后更新时间」字段（飞书 API 类型 1001，自动维护）
3. 修改 `_compute_field_updates`：对 6 个 LWW 字段比较两端时间戳
4. 修改 `update_*` 方法：自动维护 `local_updated_at`
5. UI 改进：去掉字段归属警告（因为现在是真正双向了）
6. 测试覆盖 LWW 逻辑

### LWW 时钟漂移处理

- 飞书「最后更新时间」是系统字段，精度毫秒
- 本地用 `datetime.now()`，精度秒
- 比较时本地时间转换为毫秒
- 不需要容差：因为「人工字段」用户不会在 1 秒内连改两次

## 🔄 分支与版本管理

| 分支/Tag | 状态 | 说明 |
|---|---|---|

### 如何切换

```bash
# 使用方案 A（稳定版）
git checkout main
# 或具体版本
git checkout v2.1.0-sync-a

# 尝试方案 B（开发中）
git checkout feature/sync-v3-lww

# 方案 B 失败时回退
git checkout main
git tag -d v2.1.0-sync-a  # 如需重打 tag
```
