# 单作品采集页（/collect/detail）交互设计方案 v3

> 版本：v3.2 | 日期：2026-08-17
> 范围：前端交互逻辑重设计（基本功能与后端 API 保持不变）
> 关联文件：`app/templates/collect_detail.html` · `app/static/js/collect_detail.js` · `app/static/css/style.css`
> **v3 修订说明（依据用户逐条反馈）**：
> 1. 链接输入框：清空/粘贴按钮悬浮于右下角，不再单独一行；删除「示例」按钮，改为输入框内灰色 placeholder 示例文字。
> 2. 三种模式（解析 / 一键下载 / API）确认是**并列动作**而非步骤：解析=两步（解析→结果→再下载）；一键下载=快捷执行，依赖下载设置但未改时用默认值；API=仅展示，点击弹出悬浮提示（不切换主体）。
> 3. 三个模式按钮在同一位置展示、视觉同组但**以填充强度区分主次**（Filled > Tonal > Ghost），统一蓝色系，与全局风格一致；**解析为最常用功能 → Filled 主色，一键下载 Tonal，API 弱化且尺寸略小**。
> 4. 下载设置按模式分组并用「归属标签」标注；**设置卡可折叠**（默认折叠为摘要行，仅显示保存目录）；两段之间不再设段标题（归属标签已足够）。
> 5. 下载方式（本地/浏览器）从下载设置中移除，移到解析结果卡片——在准备下载该资产时提供两种选择。
> 6. 精简说明文字（自用工具，仅保留必要提示）；命名模板预览带「预览:」前缀。

## 1. 现状分析

| # | 问题 | 影响 |
|---|------|------|
| P1 | 链接输入无即时反馈，粘贴后只有计数 | 用户盲点动作，出错后才暴露 |
| P2 | 三种模式（解析/一键下载/API）平铺且无主次，模式语义弱 | 误点率高，感知不到"我该用哪个" |
| P3 | 下载设置把三模式所需字段堆在一起，靠禁用表达归属，难以区分 | 用户不知道哪些设置对自己当前模式生效 |
| P4 | 下载方式（本地/浏览器）混在全局设置里，但它只对"解析结果下载"有意义 | 概念错位，设置卡被无关选项占用 |
| P5 | 作品卡片信息密度失衡 | 扫描效率低 |
| P6 | 资产勾选选中数反馈弱 | 批量下载需数格子 |
| P7 | SSE 进度面板纯文本日志，阶段感弱 | 长任务无法判断进度 |
| P8 | 下载历史失败原因与重试入口不显眼 | 出错恢复路径弱 |

## 2. 设计目标与原则

### 2.1 设计目标

1. **模式即动作** — 三个模式按钮在同一位置、同一视觉容器内，点击即执行对应行为（解析两步走 / 一键下载 / API 提示），互不依赖、随时可点。
2. **输入即反馈** — 粘贴后立即平台识别 + 有效性预检。
3. **设置归属明确** — 下载设置用「通用 + 模式归属分组」组织，每个专属字段带归属标签，不再靠禁用猜测。
4. **下载方式就近出现** — 本地/浏览器选择只在"下载该资产"那一刻出现，从全局设置中移除。
5. **状态零遗漏** — 解析/下载各阶段有可视状态。

### 2.2 设计原则

- **并列不递进**：三种模式是并列入口，无顺序依赖。
- **就近操作**：下载相关选择（本地/浏览器）跟随下载动作出现。
- **默认值兜底**：一键下载未修改设置时直接用默认值，保证"一键"成立。
- **一致性**：沿用 M3 设计语言（`--dh-*` / `--md-*`）。

```
│   ▸ 段B 归属:  「解析」解析模式 / 「一键」附带下载             │
├──────────────────────────────────────────────────────────────┤
│ ④ 处理结果区（quick/resolve 共用输出）                       │
│   空态 → 作品卡片（可勾选资产）                               │
│   卡片「下载选中」→ 弹出 [📥本地 | 🌐浏览器] 选择 → 执行       │
├──────────────────────────────────────────────────────────────┤
│ ⑤ 下载历史（常驻，可折叠）                                   │
└──────────────────────────────────────────────────────────────┘
```

### 3.1 三模式行为模型

| 模式按钮 | 点击行为 | 依赖设置 | 结果呈现 |
|----------|---------|---------|---------|
| 🔍 解析 | 开始解析（SSE 流式出卡） | 解析模式选择器 | 卡片可勾选资产 → 下载时选 本地/浏览器 |
| ⚡ 一键下载 | 解析 + 下载一体执行 | 保存目录/命名模板/附带下载（未改则默认值） | 卡片自动带下载状态 |
| 🌐 API 请求 | 弹出悬浮提示（仅展示） | 无 | 浮层展示 API 地址/Key/说明 |

**关键交互规则**：
- 三个按钮**可重复点击**（再次执行）；执行中按钮进入 loading 态并防重复提交。
- 点击 API 请求**不切换主体内容**，仅弹出浮层；浮层可关闭，主体（输入/设置/结果）保持不变。
- 解析结果跨模式保留（切换动作不清空已解析卡片）；只有重新执行解析/一键下载才重置输出区。

## 4. 核心交互逻辑详解

### 4.1 链接输入区：悬浮操作 + placeholder 示例

**布局**：文本框右下角悬浮两个图标按钮（📋快捷粘贴 / 🗑清空），不占独立行。

```
┌──────────────────────────────────────────────┐
│ https://www.douyin.com/video/7300...          │
│ https://www.tiktok.com/@name/video/7300...    │
│                                        [📋][🗑]│ ← absolute 右下角
└──────────────────────────────────────────────┘
```

**placeholder 示例（灰色文字）**：
```
粘贴作品链接，每行一个，例如：
https://www.douyin.com/video/7300...
https://www.tiktok.com/@name/video/7300...
```
输入后 placeholder 自动消失；「清空」恢复 placeholder。

**链接识别**：输入/粘贴后逐行解析 → 行尾平台徽章（抖音黑/TikTok青/小红书红）或「无法识别」红标；汇总条 `[N 个链接 · M 有效]`，有无效时变橙。预检失败的行不随请求发送，但保留原文。

### 4.2 模式操作区：同一位置 · 三种模式 · 主次区分

三个按钮放在**同一个圆角容器**内（表明同一族），视觉以**填充强度**区分主次（统一蓝色系，与全局一致）：

| 按钮 | 视觉 | 说明 |
|------|------|------|
| 🔍 解析 | Filled（蓝底白字） | **最常用**，填充最强 |
| ⚡ 一键下载 | Tonal（浅蓝底+蓝字） | 快捷下载，次级 |
| 🌐 API 请求 | Ghost（透明底+虚线边框+灰字，padding 略小） | 仅展示入口，刻意弱化 |

**区分手段**：填充强度（Filled > Tonal > Ghost）+ API 尺寸略小；**不额外引入红/橙等色相**，保持整体风格统一。

**与代码映射**：点击分别调用现有 `resolveSingleWorks()` / `quickDownload()`；API 用现有 `loadApiInfo()` 数据渲染浮层（不切换 `api-mode-panel` 为主视图）。

### 4.3 下载设置卡：可折叠 + 通用字段 + 模式归属分组（核心设计）

**解决目标**：三种模式所需设置不同，全部堆在一起+禁用表达不清。方案——**单卡两段式 + 可折叠**：

```
┌────────────────────────────────────────────────────────┐
│ ⚙ 下载设置   D:\Downloads\DoukHub                    ▾ │ ← 折叠头（默认折叠，仅显示目录）
├────────────────────────────────────────────────────────┤
│ 保存目录   [ D:\Downloads\DoukHub______ ] [📁]           │
│ 命名模板   [ {create_time} {author} {title} ▾ ] [⚙]     │
│            右侧小字: 预览: 2026-08-15 阿斌的日常 夏日限定 │
│ ────────────────────────────────────────────────────   │
│ 「解析」  解析模式  [ 自动(API+TTD) ▾ ]                  │
│ 「一键」  附带下载  [🎵音乐][🖼静态封面][🎬动态封面]       │
└────────────────────────────────────────────────────────┘
```

- **折叠**：默认折叠为一行摘要（**仅显示保存目录**，不放文件名预览），点击展开完整设置；状态可记忆。设置项有默认值，未展开直接用默认（保证"一键"成立）。
- **段 A（通用）**：保存目录、命名模板 —— 解析与一键下载共用，无归属歧义；两字段采用**相同的 label+控件 结构**（命名模板的文件名预览并入 label 行右侧小字，带「预览:」前缀），左右对齐。
- **段 B（归属分组）**：字段前带**归属胶囊标签**（「解析」/「一键」），明确该设置只对对应模式生效，无需禁用互斥，**不再设段标题**。
- **下载方式已移除**（见 4.4），不再在此处放任何提示。
- **默认值兜底**：所有字段有默认值，未修改即用默认。

**为什么不用"按模式切换设置卡"**：解析与一键下载共用目录/模板，物理分开会造成重复设置与切换闪烁；归属标签方案信息密度低、无状态切换，扫一眼即知"哪个设置归谁"。

### 4.4 下载方式：从设置移到结果页（下载时选择）

**触发点**：解析结果卡片内点击「下载选中」（或单资产下载）→ 弹出小浮层：

```
┌──────────────────────┐
│ 下载 3 个资产          │
│ [📥 本地下载]          │ ← 默认高亮（记住上次选择）
│ [🌐 浏览器下载]        │
└──────────────────────┘
```

- 选择后执行，浮层关闭；下次默认记住上次选择（localStorage 或会话变量）。
- **一键下载固定本地**（语义即"下载到本机目录"），不弹选择。
- 与现有 `currentDownloadMode` 兼容：解析结果下载时设置该值，一键下载强制 local。

### 4.5 作品卡片（输出区）

同 v2 信息层次（作者行/描述/媒体/互动/音乐/标签/资产列表/状态），新增：
- 工具栏「下载选中 N」点击 → 弹出 4.4 的选择浮层。
- 资产勾选整行高亮 + 底部浮动操作条跨卡片聚合（保留）。

### 4.6 进度面板（阶段化）

同 v2：四阶段流程条（解析链接→获取详情→下载资产→完成）+ 总数/成功/失败指标 + 日志。失败行「重试该链接」。

### 4.7 下载历史

同 v2：折叠 + 筛选 + 失败重试。

## 5. 状态系统设计

| 状态 | 颜色 | 语义 | 使用位置 |
|------|------|------|---------|
| 成功 | 绿 `--md-success` | 完成 | 徽章/进度/历史/Toast |
| 警告 | 橙 `--md-warning` | 部分失败 | 无效链接汇总、一键下载主色 |
| 错误 | 红 `--md-error` | 失败 | 链接预检/下载失败/历史 |
| 进行中 | 蓝 `--dh-accent` | 执行中 | 进度条/阶段高亮/按钮 loading |
| 中性 | 灰 `--dh-text-muted` | 待办/禁用 | 空态/API ghost 按钮 |

动效：卡片插入 300ms fade-slide；按钮 loading 用 spinner；浮层 150ms fade+scale；`prefers-reduced-motion` 降级。

## 8. 实施建议（前后端改动清单）

### 前端（本次设计范围内）
1. `collect_detail.html` — 结构重组：输入框悬浮操作；三模式动作按钮容器；下载设置卡两段式；结果页下载方式浮层；API 浮层。
2. `collect_detail.js` — 新增：链接预检；三按钮动作分发（复用 `resolveSingleWorks/quickDownload/loadApiInfo`）；下载方式浮层与记忆；跨卡片选中聚合；阶段化进度渲染。
3. `style.css` — 新增约 140 行：悬浮操作、模式容器三级按钮、归属标签、下载浮层、资产行高亮、阶段流程条。

### 后端（可选增强，非阻塞）
1. 解析失败返回结构化错误 `{link, error}`（前端精确重试）。
2. 跨作品批量下载接口（替代前端循环）。

### 风险与权衡
- 链接预检为前端启发式，最终以后端解析为准（SSE 错误兜底）。
- 一键下载"默认值兜底"依赖设置默认值已正确配置（首启时从配置加载）。
- API 浮层展示的信息与现有 `api-mode-panel` 数据同源，避免双份维护（浮层复用同一数据渲染）。
