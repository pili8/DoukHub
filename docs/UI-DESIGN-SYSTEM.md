## 1. 核心原则

| 原则 | 说明 |
|------|------|
| **全 token 化，禁止硬编码颜色** | 所有颜色一律用 `var(--dh-*)`，不得写死色值（硬编码会导致深浅主题不跟随、多页不统一，历史教训：日志框 `#1a1c1e` 硬编码） |
| **深浅主题自动跟随** | 项目有完整暗色模式（`data-theme` 切换 + localStorage 记忆 + 跟随系统），用 token 即自动适配，零额外代码 |
| **风格统一优先** | 新组件先对齐项目已有范式（按钮 6px 圆角、卡片白底细边框、胶囊容器），不引入跳色 |
| **自用工具，精简文字** | 说明文字只留必要提示，删冗长解释 |
| **层次用填充强度表达** | 主次用 Filled / Tonal / Ghost 或浅深两档蓝，不用不同色相跳色 |

## 2. 主题机制

- 控制方式：`<html data-theme="light|dark">`（`style.css` 中 `:root` 与 `:root[data-theme="dark"]` 分别定义全部 token）
- 切换逻辑：`base.html` 内联脚本——`localStorage` 记忆用户选择，无记忆时跟随系统 `prefers-color-scheme`
- **规则：写样式永远引用 `var(--dh-*)`，让主题自动切换生效**

## 5. 语义色（状态 / 进度场景）

| 语义 | Token | 浅色 | 深色 | 用途 |
|------|-------|------|------|------|
| 进行中 / 信息 | `--dh-accent` | 蓝 | 亮蓝 | 日志 info、进度条、计数卡"总数" |
| 成功 | `--dh-success` | 绿 | 亮绿 | 日志 ok、分段条完成段、计数卡"成功" |
| 失败 | `--dh-danger` | 红 | 亮红 | 日志 err、分段条失败段、计数卡"失败" |
| 警告 | `--dh-warning` | 橙 | 亮黄 | 日志 warn、警告提示 |

**统一约定：进度 / 状态场景下，蓝=进行中、绿=成功、红=失败、橙=警告，全项目一致。**

## 7. 布局与间距

- 基准间距 16px；卡片内边距 20px；卡内区块间距 16px
- 单作品采集页固定四卡片结构：**作品链接 → 进度 → 资产结果 → 下载历史**
- 输入框操作按钮（粘贴 / 清空）悬浮于右下角，不占独立行
- 资产列表行高紧凑（缩略图 40px），超出限高滚动

## 8. 交互惯例

- **输入即反馈**：链接输入后即时预检，统计条一行汇总（数量 · 匹配数 · 平台计数），无效链接可点击定位
- **模式并列**：同一位置三按钮表示三种模式（解析 / 一键下载 / API），按钮动作 + 设置项联动
- **低频内容折叠**：音乐 / 封面等低频资产收进折叠组，默认收起只占一行
- **进度流式展示**：分段彩色进度条（完成=绿 / 进行中=蓝 / 失败=红 / 未到=灰）+ 当前消息 + 计数卡 + 日志行；解析=2 段、下载=3 段
- **下载方式**：本地 / 浏览器选择放在下载动作时弹出（不放在设置里）
- **ESC / 点遮罩关闭一切浮层**（2026-09-17 立规，2026-09-20 统一实现）：见 §17。
  多浮层叠加时**只关最上层**；层级的权威判定不是 DOM 顺序（确认框写在任务面板之前，
  却必须压在它上面），而是 z-index + 视口中心命中测试。

## 10. 设置页结构（2026-08-21 定稿）

> 「整体设置页面」采用**分组 Tab + 折叠卡**，不做长滚动页。本节为结构决策记录。

### 10.1 分组 Tab 导航

- 顶部**分组 Tab**（DoukHub配置 / 下载与文件 / 内核服务 / 功能配置），点击切换面板（`.settings-group.active` 显隐），**不再滚动长页**。
- 组内仍可折叠卡（`.settings-card.open`）。
- 保留 `scrollToGroup` 兼容旧入口；支持 URL hash 直达分组（`#group-download`），供采集页「管理模板」等外部跳转。
- 深色主题 / 交互惯例沿用全 token 规范。

### 10.2 下载与文件分组结构

| 卡片 | 内容 |
|------|------|
| **保存方案** | 双卡横排：**增量采集**（按账号归档，根目录+平台/账号自动层级） / **单作品采集**（直存，默认目录留空则用增量根目录）；各卡含「编辑命名」直达统一编辑器 |
| **文件命名规则** | 统一命名编辑器：增量模板 / 单作品模板 小胶囊切换；字段**拉平** |
| **下载内容选项** | 增量附属下载（音乐/封面/大小上限/导出格式）；单作品附带下载在采集页「一键下载」设置 |

### 10.3 命名统一（字段拉平）

两套引擎字段**在 UI 层合并为同一套**，保存时按方案映射回引擎字段：

| UI 字段 | 增量引擎键 | 单作品引擎键 |
|---------|-----------|-------------|
| 发布时间 | `create_time` | `create_time` |
| 作品类型 | `type` | `type` |
| 作者 | `nickname` | `author` |
| 标题 | `desc` | `title` |
| 作品ID | `id` | `id` |
| 账号UID | `uid` | —（仅增量，角标） |
| 账号标识 | `mark` | —（仅增量，角标） |
| 平台 | —（仅单作品，角标） | `platform` |

- 编辑器同一套 chips，非当前方案可用字段自动隐藏，专属字段带「仅增量 / 仅单作品」角标。
- 单作品模板支持多模板 + 默认模板 + 「复制为增量」；字段编辑自动同步回当前模板并防抖持久化。
- **兼容性**：只改了前端 UI 与映射，后端 API（`/api/collection/defaults` 存 `name_format`、`/api/collection/single-work/preferences` 存 `{author}/{title}`）未变，存量配置零迁移。

### 10.4 共享命名工作台（2026-08-21 晚定稿 v6 → 落地）

> 用户批准 v6 布局原型，落地后的真实结构：**卡片内不再有命名编辑器**，统一收进**底部滑出式共享命名工作台**（单一 DOM 实例）。

#### 10.4.1 卡片区（两大组：单作品采集 / 增量采集）

| 组 | 内容 |
|----|------|
| 单作品采集 | 「保存目录」分区（方案目录 + 浏览，留空用增量根目录）+「命名」分区（**摘要行** + 「编辑模板」按钮，紫色强调） |
| 增量采集 | 「下载目录」分区（根目录 + 浏览 + 平台/账号目录树）+「命名」分区（摘要行 + 编辑模板，绿色强调）+「附属下载」分区（2 行格：第 1 行 音乐/动态封面/静态封面 开关；第 2 行 **文件大小上限在前**、**数据导出格式在后**） |

- 摘要行实时显示字段示例 + `.mp4`，字段顺序改动即时同步；「每作品独立子文件夹」开关已从批量卡移入工作台。

#### 10.4.2 底部共享命名工作台（`.workbench`，单一 DOM 实例）

- 触发：任一卡片「编辑模板」→ `openWorkbench('single'|'batch')`；遮罩点击 / 关闭按钮收起。
- 结构自上而下：
  1. **作用域胶囊**（单作品 / 增量）：`wbScope(s)` 切换，读写各自独立的 `tplState[scope].parts`；
  2. **模板管理条**（`#wb-tpl-sel`）：单作品=方案下拉（含默认标记）+ 新建 / 重命名 / ★设默认 / 删除 / 「设为增量默认」（`dupToBatch`，复制后自动切到增量作用域展示结果）；增量=固定「增量默认模板」占位（引擎级，无多方案）；
  3. **字段池**（`#wb-pool`）：chips 点击加入/移除命名，专属字段带「仅增量 / 仅单作品」角标；
  4. **排序带**（`#wb-belt`）：已选字段拖动换位、✕ 移除；
  5. **存储**（仅增量作用域显示）：「每作品独立子文件夹」开关（唯一保留的引擎级选项，`folder_mode`）；
  6. **预览**（`#wb-pv`）：文件名实时示例（分隔符 `-` 已固化）。
- JS 契约：`renderTplEditor(scope)` 幂等（摘要常驻 + 面板只渲染当前作用域）；`templateDragStart(event, scope, index)` 拖动签名修正了旧版参数错位；保存映射与 §10.3 一致，后端 API 未变。

## 11. 全局视觉标准 v2 —— 三层表面 + 蓝色强调（2026-09-05 草案，待确认）

> 本节将 §1-6 的令牌规范升级为**全站页面的强制标准**：所有页面（含表浏览、数据概览、备份、同步各页）新增/改动 UI 时逐条对照。
> 依据：v2.2.6（表浏览筛选面板）、v2.2.7（全局界面统一）两轮落地实践沉淀，已核对与 style.css / 各模板实现一致。

### 11.1 三层表面体系（空间层级，全站唯一的空间语言）

| 层级 | Token | 浅色值 | 角色 | 视觉感受 |
|------|-------|--------|------|---------|
| L0 页面背景 | `--dh-background` | `#FBFAF7` 暖白 | 最底层画布 | 平铺 |
| L1 卡片表面 | `--dh-surface` | `#FFFFFF` | 卡片 / 面板 / 弹窗 | 浮起（靠 1px 边框 + 阴影区分） |
| L2 降级面 | `--dh-surface-muted` | `#F5F2EC` 米色 | 日志、输入区、胶囊底、次级信息 | 凹下去、退后 |

**米色的正名**：米色是**降级面**，不是"着重面"。它的本职是让白卡浮起来、让次要内容沉下去。真正的"着重"是蓝色（实心按钮 + accent-soft 选中态）。

红线：
1. 一层卡片内**只套一层米色**（米色套米色会糊成一团）；
2. 米色块对比极弱，必须靠边框或内容自身站住，不能单独承担分区；
3. 弹窗、面板一律用 L1 白底，不得用米色打底。

### 11.2 蓝色强调的唯一性

| 强度 | 样式 | 用途 |
|------|------|------|
| 最强 | 实心蓝 `--dh-accent` 白字 | **主操作**，一屏内只允许一个 |
| 次强 | `--dh-accent-soft` 浅蓝底 + 蓝深字（tonal / halo） | 选中态、筛选高亮、次级主打项 |
| 中 | 白底 + 1px 边框描边（`.btn-secondary`） | 次要操作 |
| 弱 | ghost 灰字虚线框 | 仅展示型入口 |

- **选中态 halo 模式**：`accent-soft` 底 + `--dh-accent` 深字（+ 可选 1px 蓝边），用于筛选按钮选中、Tab 激活、列菜单选中项。
- 一屏内蓝色实心按钮 > 1 个即视为违规；"一屏"指视口内同批操作区。

### 11.3 文字与对比度红线

- 三档文字：`--dh-text`（正文）/ `--dh-text-secondary`（次级）/ `--dh-text-muted`（弱化）。
- `--dh-text-muted`（`#9C9387`，对白底约 **2.7:1**）**只允许用于辅助小字**（时间戳、计数、占位符），禁止承载正文——正文 AA 要求 4.5:1。
- 实心蓝按钮白字约 6.3:1，达标；深色模式下语义色自动提亮，无需逐页适配。

### 11.4 状态与语义色（全站唯一约定）

**语义约定：蓝 = 进行中/信息，绿 = 成功，红 = 失败，橙 = 警告。** 进度条分段、计数卡、日志行、状态徽章全部遵守，不得换色相。

| 场景 | 规范 |
|------|------|
| 表浏览状态胶囊 | halo 浅底 + 深字（沿用）：待解析=灰、已就绪=蓝、已生成=绿、已删除=橙、解析失败=红 |
| 任务/历史状态 | 一律映射 `--dh-warning / --dh-accent / --dh-success / --dh-danger` 语义令牌，禁止 JS 里写死 hex |
| 日志行 | `.log-ok / .log-err / .log-info / .log-warn` 四类 |

⚠️ **徽章只承载"会变化的状态"**。`.workflow-status` 这类胶囊（配 `pending`/`success`/`danger` 变体）
表达的是**状态** —— 用户看到它就是准备"据此做点什么"。把**恒定不变的信息**塞进同一种形态
（写死的时区名、固定的版本号、不会变的默认值），会让"胶囊 = 状态"这个视觉符号整体失去信号价值，
用户会开始忽略所有胶囊，真正需要他注意的状态也被一起忽略。
这类信息**要么删掉，要么降级成 12px `--dh-text-secondary` 小字**，不要借用徽章外形。
（实例：2026-09-21 移除「调度概览」里那颗硬编码的「时区 Asia/Shanghai」胶囊 ——
它是 `scheduler.py` 里的常量、用户改不了，且在新建弹窗里已按需提示。）

- **页局部补充色模式**（如设置页紫色）：在该页 `<style>` 顶部定义 `--dh-purple / --dh-purple-soft` 两枚页局部令牌（明暗各一档），页面内只引用令牌；全局 `style.css` 不为其扩表。

### 11.5 复用组件规范（v2.2.6 / v2.2.7 已落地，新页面直接套用）

| 组件 | 类名 | 规范要点 |
|------|------|---------|
| 日志面板 | `.log-panel` / `.workflow-log` | L2 米色底 + 等宽字体 + 语义色行；**禁止深色黑底**（"终端感"靠等宽字体与语义色行表达，不靠黑底） |
| 空状态 | `.empty-state` | 三段式：`es-title`（14px/600）+ `es-desc`（12px muted，可省）+ `es-action`（主/次按钮，可省）；小容器加 compact 变体；图标居中 |

## 12. 深色模式与对比度硬约束（2026-09-17 全站审计沉淀，强制）

> 依据：v2.2.8 全站界面审计（16 路由 × 明暗双主题共 32 次实测）。
> 以下缺陷**只在渲染态暴露**，静态搜色值是查不出来的 —— 新增/改版后必须实测深色。

### 12.1 表单控件必须显式或继承文字色

`button / input / select / textarea` 的 `color` 默认取浏览器系统色（ButtonText / FieldText，**恒为黑**），
**不继承父级**。只写背景、不写文字色的按钮，浅色下看似正常，深色下就是黑字压暗底（实测 1.24:1，近乎不可见）。

- 全局已在 `style.css` 兜底：`button, input, select, textarea { color: inherit; }`
- 组件类若自定义背景色，**必须同时给出 color**，不得只设 `background`。

### 12.2 "实心强调面上的前景色"唯一走 `--text-on-accent`

任何 `background: var(--dh-accent)` / `var(--accent-active)` 的实心面，其文字、图标、左侧指示条颜色
一律用 `var(--text-on-accent)`（= `--md-on-primary`），深浅主题各得 6.3:1 / 8:1。
**禁止硬编码 `#fff`** —— 深色模式亮蓝底上白字只有 2.2:1。

### 12.3 语义色用于文字时的对比度

| 令牌 | 浅色值 | 对白底 | 结论 |
|------|--------|--------|------|
| `--dh-accent` | `#0061A4` | 6.3:1 | ✅ 可直接作文字 |
| `--dh-danger` | `#C2410C` | 5.0:1 | ✅ |
| `--dh-warning` | `#B45309` | 4.5:1 | ✅ 临界可用 |
| `--dh-success` | `#15803D` | 4.6:1 | ✅（原 `#16A34A` 仅 3.16:1，已调深） |

- 语义色作**文字**必须 ≥ 4.5:1；作**图形 / 边框 / 进度条** ≥ 3:1 即可。
- 大数字、关键指标**不得用 `--dh-text-muted`**（2.4~2.7:1），它只服务时间戳 / 计数 / 占位等辅助小字。

### 12.4 操作列按钮一律降级

表格 / 列表**每行重复出现的操作按钮**（重试、详情、编辑）用 `.btn-secondary`（描边）或图标按钮，
**禁止 `.btn-primary`** —— 一屏 10+ 个实心蓝会淹没页面主操作。实心蓝只留给当前视图的主操作。

### 12.5 审计口径（可复用）

实测五项：① 实心强调元素计数（一屏 ≤1，导航 / tab 激活不计）；② 文字对比度 < 4.5:1 清单（fs ≥ 12px）；
③ 控制台错误；④ `scrollWidth > innerWidth` 横向溢出；⑤ 深色下是否存在 `rgb(0,0,0)` 文本。

## 13. 表单控件统一基线（2026-09-17 控件审计沉淀，强制）

### 13.1 铁律：控件必须命中已定义的样式

**任何"看起来像输入框 / 下拉 / 文本域"的元素，都必须命中 `.form-group input|select|textarea` 或 `.input` 之一。
禁止只写 class 名而不落样式。**

历史教训：全站 4 处 `class="input"` 在 CSS 中没有任何定义，一直掉到浏览器默认样式
（`2px rgb(118,118,118)` 边框 + 直角 + 仅 **19px 高**），高度只有旁边控件的一半 ——
这类"半截高、粗灰边、直角"的控件是风格不统一最刺眼的来源，且**浅色下不易察觉**。

### 13.2 统一参数（不得逐页另立）

| 属性 | 值 | 说明 |
|---|---|---|
| 高度 | `min-height: 34px` | 与 `.btn`(34px) 严格等高，并排不错位 |
| 圆角 | `var(--dh-radius-sm)` = 6px | 与 `.btn` / `.path-pill` 同族 |
| 边框 | `1px solid var(--dh-border)` | hover → `--dh-border-strong`（**不得**用近黑的强调色，过重） |
| 焦点环 | `0 0 0 3px var(--dh-accent-soft)` | 键盘可见性 |
| 字号 | 13px（窄屏 15px） | 与正文一致 |
| 禁用 | `--dh-surface-muted` 底 + `--dh-text-muted` 字 | |

⚠️ **`min-height: 34px` 并不能保证"看起来都是 34px"**（2026-09-20 实测）：

| 控件 | 实测高度 | 原因 |
|---|---|---|
| `<input type=text>` | 34px | 恰好达标 |
| `<select>` | **35px** | 原生下拉框有内部固有高度 |
| `<input type=time>` | **35.6px** | 同上，外加时钟图标 |

三种控件**横排一行时肉眼可见差一截**。要真正统一，必须在需要精确对齐的容器里
**写死 `height`**（而非只给 `min-height`）：

```css
/* 作用域限定在容器内，用 id 提特异性；否则压不过 .form-group input/select */
#xxx-modal .dh-modal-box select,
#xxx-modal .dh-modal-box input[type="time"] { height:34px; min-height:34px; }
```

⚠️ **两条必须同时记住的覆盖规则**：

1. **`min-height` 抬不动已定死的 `height`**：桌面钉了 `height:34px`，
   移动端媒体查询只写 `min-height:40px` **无效**，必须再显式写一遍 `height:40px`。
2. **媒体查询覆盖要连"属性选择器数量"一起算**：
   `#modal .box input[type="time"]`（2,3,1）**强于** `#modal .box input`（2,1,1）——
   窄屏那条若只写泛化的 `input`，会被桌面基线反压。
   → 移动端规则要把具体分支抄全（`input, select, input[type="time"], ...`）。
   **`input[type=x]` 的标签名和属性各算一分，别只数 id/class。**

**按钮类的内容居中**统一用 `inline-flex + align-items:center + justify-content:center`，
**不要**用 `display:block + text-align:center`（那只管水平，垂直靠 `line-height` 撑，随字体变）。

**弹窗右上角 ✕（`.dh-modal-close`）同样纳入 34px 基线**（2026-09-20）：
定义在 `base.html`，全站 9 处弹窗共用（确认框 / 后台任务面板 / 磁盘面板 / 定时任务新建与历史 /
采集方案管理 / 批次详情 / 备份清理 / 目录选择器）。原为 30px，比控件矮一截 → 统一 34×34。
⚠️ 它由 `base.html` 全局定义，**改一处即全站生效**，不需要逐页覆盖。

### 13.3 路径 / 目录字段三件套

- **`.path-pill`（只读路径胶囊）**：柔和底 + 强调色图标 + 等宽路径（超长省略、`title` 悬停看全）+ 右侧柔和图标按钮。
  用于"当前目录"展示，**禁止**用灰底贴边 mono 文字或裸文字行。
- **`.field-affix`（输入框内嵌按钮）**：输入框与"选择文件夹"按钮合成一个控件（按钮内嵌右端），
  **禁止**在输入框旁挂竖排按钮列。
- **`.field-actions`**：操作按钮右对齐横排；**`.field-group + .field-group`** 用**虚线**分隔同卡片内的次级分组。
- 配套：`.field-label`（字段标签）、`.field-hint`（提示小字）、`.icon-btn-soft`（柔和图标按钮）。

### 13.4 裸奔控件扫描（可复用口径）

用 Playwright 遍历全站**可见**的 `input / select / textarea`，按 computed style 分组；凡同时命中
`border-width: 2px` + `border-radius: 0` + `border-color: rgb(118,118,118)` 的，即为掉到浏览器默认样式的控件。

> ⚠️ **静态扫描（只比对 class 名）会误判**：属性选择器命中的控件（如 `.ext-pill input[type="checkbox"]`）
> 在 class 扫描里表现为"无定义"，实际已有样式。判定口径**必须以浏览器实测为准**。

### 13.5 勾选框 / 单选框

```css
:where(input[type="checkbox"], input[type="radio"]) { accent-color: var(--dh-accent); }
```
`:where()` 特异性为 0，AG Grid 等自带主题仍可覆盖，不会误伤第三方组件。

### 13.6 已知遗留（待决策，勿在未讨论前动手）

- **select 原生箭头**：统一需 `appearance:none` + 自定义箭头，但各页 select 已有各自
  `background` 简写声明（含 ID 选择器）会覆盖之，收益不抵风险。
- **双图标库并存**：项目同时加载 lucide 与 Phosphor，9 个模板共 117 处 `ph ph-*`，
  两套线宽/比例有细微差异。统一需成批替换 + 图标名映射，属独立课题。**（2026-09-17 用户决定：不做）**

## 14. 统计数值的颜色语义（2026-09-17 沉淀，强制）

### 14.1 分类计数禁用语义色

统计条里的数字分两类，**颜色待遇必须区分**：

| 类型 | 例 | 用色 |
|---|---|---|
| **主指标**（本次任务的总量） | 可采 / 账号总数 | `--dh-accent`（蓝色文字，非实心） |
| **分类计数**（把主指标拆开的明细） | 首次 / 增量 / 待处理 | `--dh-text`（正文色） |
| **弱化计数**（本轮不处理的部分） | 跳过 | `--dh-text-secondary` |
| **真正的状态结果** | 成功 / 失败 | `--dh-success` / `--dh-danger` 保持不变 |

原因：`橙=警告、绿=成功` 是状态语义。用橙色表示"首次"、绿色表示"增量"，
用户会把"分类"读成"状态"，是典型的语义撞车。**只有"成功/失败"这类结果才配用语义色。**

> 一屏统计条里 `--dh-accent` 只给主指标一个，其余中性化 —— 与 §11.2「蓝色强调的唯一性」同源。

### 14.2 大数字不得使用 `--dh-text-muted`

`--dh-text-muted`（浅色 `#A39E96`）**只服务时间戳 / 占位符这类 ≤12px 辅助小字**（约 2.4:1）。

统计条数字是 **20px / 700**，按 WCAG 属"大字号"，**下限是 3:1**；浅色底上它只有 **2.38:1**，
连大字号线都不到。需要弱化外观时用 `--dh-text-secondary`（浅色 6.5:1 / 深色 9.4:1）。

**判定口径**：任何数字/文字元素，先按字号算门槛（≥18.66px 或 ≥24px 取 3:1，否则 4.5:1），
再决定能否用弱化色 —— 不要因为"它看起来是次要信息"就套 `--dh-text-muted`。

## 15. 移动端适配基线（2026-09-17 沉淀，强制）

> 本轮首次把视口压到 375 / 768px 实测（此前所有审计都在 1440px 做）。
> **"没有横向滚动"≠"可用"** —— 下面的缺陷里，前两条在 `scrollWidth > innerWidth`
> 这个检查项下**全部为 0**，是靠量几何和看渲染才发现的。

### 15.1 内容首行必须避开固定定位的汉堡按钮

汉堡按钮是 `position: fixed` 的 **(12, 12, 44×44)**，而 `.main` 的首行内容也从 (12,12) 开始
→ **两者完全重叠**，每个页面的标题首字都被压住；副标题更长时被挤成断词换行。

**强制做法**：≤768px 下给页头标题容器 `padding-left: 56px` + `min-height: 44px` +
`justify-content: center`，与汉堡同处一行。**只缩标题容器，不缩整块 header**
（否则操作按钮行也会被左移，白白浪费 56px 宽度）。

需覆盖的两种页头写法：

| 写法 | 选择器 |
|---|---|
| `.page-header` + 直挂 `h2` | `.page-header > h2` |
| `.page-header` + `.page-title-wrap` 包裹 | `.page-header > .page-title-wrap` |
| `.page-head` + `.page-title`/`.page-sub` | `.page-head > div:first-child` |

**新增页头时必须沿用这两种结构之一**，否则拿不到让位规则。

### 15.2 媒体查询断点

| 断点 | 用途 |
|---|---|
| ≤768px | 移动端主断点（抽屉导航、堆叠页头、触控目标、字号下限） |
| ≤420px | 极窄屏（仅缩小数字字号，**不得再降标签字号**） |

**页面级修正一律写进 `@media (max-width: 768px)`，桌面值一个都不改。**

### 15.3 移动端字号下限

- **正文与数据（表格 td、表单值）≥12px**，不得为"塞下更多列"降到 11px 以下。
- **标签/徽章类辅助小字 ≥11px**，且**绝不允许在 ≤420px 再降一档**（曾出现 9px）。

⚠️ **实现注意**：各模板自己的 `<style>` 在文档顺序上位于 `style.css` **之后**，
同优先级会覆盖全局规则。所以**组件的字号修正必须写在定义它的那个模板里**，
写进 `style.css` 会被静默吃掉。

### 15.4 触控目标

- 常用按钮/tab ≥ **36px** 高（实测曾出现 29px 的 tab、20px 的"全不选"）。
- 卡片内的搜索/筛选输入框 ≥ **36px**；**AG Grid 内联编辑器除外**（改它会撑高表格行高）。
- 触控修正**不得牵动表格行高**，因此禁止用通配选择器批量设 `min-height`。

### 15.5 卡片式表格（窄屏把表格行改成卡片）

窄屏卡片的常见做法是把卡片塞进 `<tr><td colspan="N">`，此时**表格宽度仍由桌面表头决定**，
卡片会被撑到远超声宽并被裁切（实测 533px vs 视口 375）。

**强制三件套**：

```css
#该表格 { table-layout: fixed; width: 100%; }
#该表格 thead { display: none; }          /* 卡片自带字段标签，表头无意义 */
.卡片体 { grid-template-columns: minmax(0, 1fr) minmax(0, 1fr); }  /* 不能用 1fr */
```

`1fr` 的隐含下限是 `min-content`，长值会把列撑爆 → **网格里放可变长文本一律用 `minmax(0, 1fr)`**。

### 15.6 移动端审计口径（在 §12.5 五项之外追加）

⑥ 标题文字左边界 vs 汉堡右边界（用 `Range.getClientRects()` 量**文字**，
`getBoundingClientRect()` 量的是边框盒，会被 `padding-left` 骗过）；
⑦ 375px 下 `<12px` 的文字清单（区分"正文数据"与"徽章标签"）；
⑧ 卡片宽度 vs 视口宽度（卡片式表格必查）；
⑨ 触控目标高度分布（<36px 清单，排除表格内行内按钮与内联编辑器）；
⑩ 页头副标题是否被挤成单字换行。


## 16. 侧边栏底部区（2026-09-20 沉淀）

> 侧栏底部是一列「采集进度 + 三个功能图标」的紧凑控件组，桌面端展开 185px / 折叠 64px
> 两种形态差别极大，是最容易出问题的一块区域。以下为定稿规则。

### 16.1 展开态 = 白卡 + 实描边（不要米色内陷面）

侧栏本身是白底（`--dh-surface`）。若卡片用米色（`--dh-surface-muted`）配透明边框，
在暖白侧栏上**几乎看不出边界**，观感"糊"。

**强制**：`background: var(--dh-surface)` + `border: 1px solid var(--dh-border)` +
`border-radius: var(--dh-radius-sm)` + `box-shadow: var(--dh-shadow-sm)`；
悬停 → `--dh-border-strong` + `--dh-shadow-lg`。

> 靠**描边 + 极淡投影**分层，不靠底色差 —— 底色差在"白底侧栏"这个语境下不成立。

### 16.2 折叠态四个控件必须同形

采集进度图标与 footer 按钮**外观完全一致**：36×36、`--border-default` 描边、
`--bg-input` 白底、`--radius-sm` 圆角、图标 16px、hover 走 `--accent`。

固定顺序：**折叠态自上而下 = 展开态自左至右，两态一一对应** ——
`采集进度 → 磁盘状态 → 明暗切换 → 后台任务`（展开态采集卡片独占一行在最上，三个按钮平铺）。

一一对应是硬要求：映射错位时 FLIP 补间会让图标互相交叉乱飞（见 §16.9）。

彼此间距 6px，构成一列（**不再强贴**，理由见 §16.8）。
图标居中的坑见 §16.6；展开态后台贴最右见 §16.7。

### 16.3 折叠态悬停展开：原地展宽，绝不移动锚点

**这是硬约束，用于消除"悬停闪烁"**：展开时元素 `left` 保持不变、只改 `width`
（36 → 200px）。若把左沿挪走，鼠标坐标会被甩出元素外 → `mouseenter`/`mouseleave`
正反馈震荡 → 每秒来回数次闪烁。

- 包含块 `.gpc-slot` 必须**固定占位**（`width/height: 36px`），否则子元素 `absolute` 化后
  槽位塌缩、元素飞位。
- 锁宽三件套：`flex: 0 0 auto` + `box-sizing: border-box` + `width/min-width/max-width`。
- **验证口径**：悬停后每 100ms 采样宽度共 25 次，`uniqueWidths` 必须只有单一值。

### 16.4 窄容器的文案取舍：先量化，再换方案

侧栏 185px → 内容区实测仅 **136px**。「采集 67%」段占 76px 后只剩 60px，
放不下带任务名的「另 sync_v2 +1」（需 75px）。

**强制做法（2026-09-20 定稿）：文字独占第二行，而不是硬塞或截断成半个词。**

采集卡片改为纵向两行结构（`.gpc-main` 内 `.gpc-head` + `.gpc-sub`）：

| 形态 | 可用宽度 | 第一行 | 第二行 | 卡片高 |
|---|---|---|---|---|
| 展开态 | 136px | `采集 67%` + `另 2 项` | 任务名列表 | **50px** |
| 折叠态悬停 | 200px | `采集 67%` + `另 sync_v2 +1` | 不显示 | 36px |
| 窄屏抽屉 | 119px | 只有 `采集 67%` | 任务名列表 | **50px** |

- 有第二行时由 `.has-extras` 把高度从 40px 提到 50px。
- 第二行仍放不下时走 `text-overflow: ellipsis`，**完整清单写进 `title`**。
- 窄屏藏起第一行的「另 N 项」（会截成「另 2…」）—— 第二行已列出完整名单，项数是冗余信息。

> ⚠️ **不要试图用 `:hover` 展宽来"腾地方"**：父级 `.sidebar` 是 `overflow-y: auto` 的滚动容器，
> 子元素横向超出**同样会被裁掉**，宽出来的部分根本看不见。
>
> ⚠️ **窄屏媒体查询里必须写 `min-height` 而不是 `height`**：`.sidebar .global-progress-chip`
> 与 `.global-progress-chip.has-extras` **特异性相同**，而媒体查询在文件末尾 → 写
> `height: 36px` 会盖掉 50px，第二行被 `overflow: hidden` 裁掉（375px 视口实测触发）。

### 16.5 DOM 顺序变更必须同步查 JS

调整 footer 按钮顺序、或在 chip 内新增包裹层（如 `.gpc-head`）后，必须检查：
- 靠子元素序位 / `querySelectorAll` 取值的逻辑是否错位；
- 依赖布局状态的文案（如 §16.4 的两套文案）是否需要**主动刷新**，
  否则要等下一次轮询（2.5s）才更新，视觉上像漏了一拍。

### 16.6 折叠态列内控件的"对齐"要量到图标，不是量到按钮

四个控件外形（36×36 / 描边 / 白底）一致**不等于**图标对齐。

**⚠️ 元凶是包裹层宽度**：chip 内的 `.gpc-head` 在展开态是 `width: 100%`（要占满整行），
折叠态若不重置，36px 圆点里这行仍占满宽、图标按 `flex-start` 贴左沿 ——
实测图标中心 `cx=24`，而按钮都是 `32`，**差 8px**，肉眼就是"没对齐"。

**强制**：折叠态补 `.gpc-head { width: auto; justify-content: center; gap: 0 }`，
且 chip 图标尺寸取 **16px**（与 `.footer-btn svg` 同尺寸）。

**验证口径**：量**图标**的 `getBoundingClientRect().cx`，四个控件必须同为 `32`。

### 16.7 展开态：后台任务贴最右，其余靠左成组

footer 用 `align-items: center; gap: 8px`，后台按钮上加 `margin-left: auto` 推到右端，
磁盘与明暗自然靠左成组 → 鼠标从主内容区回侧栏时，右侧那个后台按钮最近。

> 不用 `justify-content: space-between`，也不用 `order`：
> `space-between` 会把三个按钮均匀铺开、看不出主次；`order` 只改绘制顺序，
> 改不了"成组 vs 分散"这个布局结果。
>
> ⚠️ `margin-left: auto` 在折叠态（`flex-direction: column`）会落到**交叉轴**上，
> 把按钮顶到右沿 → 折叠态必须重置为 `margin-left: 0`。

### 16.8 采集图标与后台按钮不必强贴

两者点开的是**同一个后台任务面板**，因此"图标下沿紧贴按钮上沿（间距 0）"这一条已废止，
统一按 6px 间距排列即可。

### 16.9 折叠/展开的形态切换必须用 FLIP（flex-direction 不可插值）（2026-09-20）

底部区在折叠态是**纵向一列**、展开态是**横向一行**，`flex-direction` 变化**没有过渡**，
不管怎么写 `transition` 都会"啪"地跳变。唯一可行做法是 **FLIP**：

| 步骤 | 动作 |
|---|---|
| First | 切换前量一遍四个控件的 `getBoundingClientRect()` |
| Last | 切 class → `void document.body.offsetHeight` 强制同步布局 → 再量一遍 |
| Invert | 给元素设 `transition: none` + `transform: translate(旧位置-新位置)` |
| Play | 下一帧 `requestAnimationFrame` 里改成 `transform: translate(0,0)` + `transition: transform 240ms` |

**硬要求**：

- **两态顺序必须一一对应**（见 §16.2），否则图标会交叉乱飞；
- **必须清内联样式**：动画结束后 `el.style.transition/transform = ''`。
  内联 `transition` 优先级高于样式表，留着会长期压住卡片自身的 hover / peek 过渡；
- **忽略 `display:none` 的元素**（无采集任务时的卡片）：用 `getClientRects().length` 判断，
  不要用 `offsetParent`（对某些定位元素同样返回 null）；
- **时长与 `.sidebar` 的 `width .2s` 对齐**（取 240ms）：栏宽、卡片尺寸、图标位移同时到位；
- **卡片尺寸要能插值**：展开态宽度必须写 `calc(100% - 24px)` 而不是 `auto`
  （`auto ↔ 具体值`不可插值，会在折叠瞬间跳变）。
- 切换前务必**先收掉 `is-peek`**，否则 First 量到的是 200px 悬停展开态的矩形。

**验证口径**：切换后在浏览器侧用 `rAF` 采样 400ms，逐帧解析 `getComputedStyle(el).transform`
的 `m41/m42`，位移非零的帧数 ≥ 5 才算补间真的在跑（跳变时只有 0~1 帧）。

### 16.10 磁盘面板：存储方案盘 + 应用数据盘，告警只认前者（2026-09-20）

**展示口径**：面板列 **存储方案（`storage_profiles`）里已启用方案**的目录所在卷，
外加**应用数据目录 `app_data_dir` 所在卷**（排在最后，标「不参与告警」）。
其余未方案化的盘一律不列。

**告警口径**（与展示口径**不同**，这是本节的关键）：
只有 **存储方案用到的卷**（接口里的 `writable=true`）才参与「低于 5GB 转红」判定；
应用数据卷 `writable=false` → **写满也不转红**。理由：数据卷写满不会让采集写不进去，
让它跟着红会把用户注意力引到错误的盘上。

> 两套口径必须同时写进面板底部文案（"统计范围" + "告警范围"各一行），
> 否则用户看到"盘列出来了却不报警"会以为是 bug。

为什么未方案化的盘不列：用户没配进方案的盘既不会往里写、也没法操作，列出来只是噪音 ——
系统盘常年"剩余不足"却又与采集无关，会让图标一直红着，反而钝化告警的信噪比。

- 同一卷被多个方案用到 → 合并成一条，标签**按方案名归并**：`本机F（增量采集 / 单作品）`。
  ⚠️ 别边扫边拼标签，否则同名方案会拼出「增量采集 · 本机F、单作品 · 本机F」这种重复文案；
- 面板里列出该卷关联的**目录路径**，用户能核对"这个盘到底是哪几根目录在用"；
- 阈值仍是 5GB（与采集启动前的空间检查同一口径）；
- **动态生效、不用重启**：后端每次请求实时读 `config.storage_profiles`，前端每次打开面板
  都重拉（侧栏图标另有 60s 轮询 + 页面恢复可见时补拉一次）。用户新加一个含 D 盘的存储方案，
  下次打开面板 D 盘就在列表里；停用/删掉方案，D 盘随之消失。
  ⚠️ 前提是**走 `PUT /api/collection/storage` 改配置** —— 直接改库会被服务内存里的副本覆盖。

> ⚠️ 路径来自用户配置 → 拼 HTML 前必须转义（`_dhEsc`），别直接字符串相加。


## 17. 浮层关闭与层级（2026-09-20 沉淀）

### 17.1 关闭方式：默认"点遮罩 = 点 ✕"

`base.html` 内置一个**通用派发器**，所有浮层无需逐个写处理：

| 触发 | 行为 |
|---|---|
| 点遮罩空白处 | 等同点右上角 ✕ |
| 按 ESC | 关掉最上层浮层（一次只关一层） |

- 识别范围：`.dh-modal-overlay` 与 `table.html` 的 `.modal-overlay`（`display !== none` 即视为已展示）。
- 关闭动作 = **点它的 ✕ 按钮**（`.dh-modal-close` / `.modal-close`），
  而不是直接调关闭函数 —— 各页关闭函数命名不统一，✕ 才是唯一权威入口。
- **防误判**：`mousedown`/`click` 的 `target` 必须都落在遮罩本身
  （否则"在框内拖选文字、松手到框外"会被当成点遮罩）。
- **取最上层**：`elementsFromPoint(中心)` 命中测试，而非 DOM 顺序
  （各 overlay z-index 相同，确认框 DOM 在前却要压在后面）。

### 17.2 豁免：`data-no-outside-close`

表单类、进行中的阻塞浮层必须加此属性 —— 误点遮罩会丢掉已填内容或打断进度。

| 浮层 | 豁免 | 理由 |
|---|---|---|
| `#migration-overlay` | ✅ | 数据迁移进行中，无 ✕ 按钮，绝不能中途消失 |
| `#preset-manager-modal` | ✅ | 采集筛选方案编辑表单 |
| `#add-record-modal` | ✅ | 新增/编辑记录表单 |
| `#save-preset-modal` | ✅ | 需输入方案名 |
| 任务面板 / 磁盘面板 / 批次详情 / 重复记录 / 导入预览 / 清理缓存 / 目录选择器 / 确认框 | ❌ 放行 | 只读信息、列表选择或无输入的表单 |

> 确认框放行是**安全方向**：点外/ESC 一律 `resolve(false)`（= 取消），永远不会误确认。

### 17.3 层级（z-index）

| 层 | z-index | 说明 |
|---|---|---|
| 移动端抽屉遮罩 / 抽屉 | 30001 / 30003 | |
| 一般浮层 `.dh-modal-overlay`（含 table.html 的 `.modal-overlay`） | **31000** | **必须高于抽屉**，否则被遮罩盖住 |
| 确认框 `#dh-confirm-overlay` | **40000** | 可能从面板里弹出，必须永远在最上层 |

**⚠️ 踩坑记录（本次实测）**：
1. 浮层原为 `20000` < 抽屉 `30001` → 移动端在抽屉里点「后台任务」，
   面板**确实打开了**却开在遮罩底下：又暗又点不动。→ 抬到 31000，
   并在 `openTaskPanel` / `openDiskPanel` 里**先收抽屉**（窄屏按钮就在抽屉内）。
2. 确认框与其它浮层同为 20000 且 DOM 在前 → 面板开着时弹确认框，
   一次 ESC / 一次点遮罩关掉的是**面板**，确认框根本没露面。→ 提到 40000。

**验证口径**：`elementsFromPoint(视口中心)` 命中的 overlay 就是"最上层"；
叠层场景下必须等于刚弹出的那个。

## 18. 特异性陷阱：容器级规则压过组件类（2026-09-20 首测，2026-09-21 扩类，强制）

> 本节讲的是**一类**坑，不是一条。已实测到三种表现：
> ① `<small>` 文字被染色（18.1~18.3）；② **写在 `<label>` 上的组件被改掉 `display`**（18.4）。

### 18.1 问题

`style.css` 里有一条**跨页生效**的规则：

```css
.form-group small, .field-hint { color: var(--md-outline); }   /* 特异性 = 21 (0,2,1) */
```

而 `--md-outline` = `#A39E96`，与 `--dh-text-muted` 同色，**在白底上只有 2.66:1**，
远低于 §11.3 / §12.3 要求的 4.5:1。

只要你的提示文字写成 `.form-group` 内的 `<small class="你自己的类">`，**就会被这条规则点名命中**。
此时只写单类选择器（如 `.sched-hint { color: var(--dh-text-secondary) }`，特异性仅 10）
**压不住它** —— 看起来"写了 color 却不生效"，实测 computed 仍是 `rgb(163,158,150)`。

### 18.2 修法

把选择器特异性提到 **≥ 21** 并靠后声明，一次性覆盖三种写法：

```css
.sched-hint,
.form-group .sched-hint,
.form-group small.sched-hint {
  font-size: 12px; line-height: 1.55; color: var(--dh-text-secondary);
}
```

变体（如 `.is-warn`）必须**同样带前缀**，否则又被打回 muted：

```css
.sched-hint.is-warn,
.form-group small.sched-hint.is-warn { color: var(--dh-warning); font-weight: 500; }
```

### 18.3 排查口径（可复用）

不要靠读 CSS 猜谁赢 —— 直接问浏览器：

```js
for (const sheet of document.styleSheets) {
  for (const r of sheet.cssRules) {
    if (r.selectorText && r.style?.color &&
        document.querySelector(SEL)?.matches(r.selectorText))
      console.log(r.selectorText, '=>', r.style.color);   // 全部命中者，最后一条即胜出
  }
}
```

**实测结论**：`.sched-hint` 浅色 **2.66 → 7.25**、深色 **10.33**，双双达标。

> ⚠️ 同类陷阱不限于 `small`：任何"容器级规则 + 低特异性自写规则"的组合都会这样。
> **给容器内某后代写样式时，特异性必须 ≥ 容器级规则。**（详见 skill `doukhub-ui-audit`）

### 18.4 变体二：**写在 `<label>` 上的组件**（2026-09-21 实测，比染色更严重）

`style.css` 里还有一条同样跨页生效的规则：

```css
.form-group label, .field-label {
  display: block; margin-bottom: 6px;
  font-weight: 600; font-size: 12px; color: var(--dh-text-secondary);
}                                                     /* 特异性 = 11 (0,1,1) */
```

它命中 `.form-group` 内的**每一个 `<label>`** —— 包括那些本身就是"组件"的 label
（`.sched-mode` 方式单选、`.sched-day` 星期多选、`.switch-item` 开关）。
这些类只写单类选择器（特异性 10），于是被逐条压掉：

| 被抢走的属性 | 后果 |
|---|---|
| `display: inline-flex` → **`block`** | ⚠️ **`align-items:center` 直接失效** → 文字贴到组件顶部，看着像"字没居中 / 被裁了" |
| `font-size: 13px` → **12px** | 同排控件字号忽大忽小 |
| `font-weight: 500` → **600** | **未选中项也是粗体** → 选中/未选中几乎分不出来 |
| 多出 `margin-bottom: 6px` | flex 行内按外边距盒居中，组件整体**比同行文字高 3px** |

**实测数据**：`.sched-mode` 文字垂直偏差 **−7px**、`.sched-day` **−6.4px**、
`.switch-item` 相对同行文字 **−2.72px**（修后分别为 **0 / 0 / +0.28px**）。

**修法** —— 组件规则加 `.form-group` 前缀把特异性提到 20，并**显式重置**被抢的属性：

```css
.sched-day,
.form-group .sched-day {
  display: inline-flex; align-items: center; justify-content: center;
  margin-bottom: 0;              /* ← 必须显式写，否则继承容器级规则 */
  height: 34px; font-size: 13px; font-weight: 500; line-height: 1;
}
```

⚠️ **连带坑**：桌面规则特异性升到 20 后，**媒体查询里原来那条单类规则（10）会反过来被压住**，
窄屏的触控放大全部失效。所以**媒体查询里那条也要带同样的前缀**：

```css
@media (max-width: 768px) {
  .sched-day, .form-group .sched-day { height: 36px; }   /* 少写前缀 = 窄屏被压回桌面值 */
}
```

**新增组件时的自检两问**：① 它是 `<label>` 吗？② 它在 `.form-group` 里吗？
两个都是 → 必须带 `.form-group` 前缀。

## 19. 定时任务频率档（2026-09-20 新增）

### 19.1 四种频率 → cron 映射

| 频率 | 生成示例 | 说明 |
|---|---|---|
| 每天 | `0 3 * * *` | 单时间点 |
| **每天多次** | `0 2,8,14,20 * * *` | 见 §19.2 |
| 每周 | `0 8 * * 1` | 周字段限制 → 一天最多一次 |
| 每月 | `0 3 1 * *` | 日字段限制 → 一天最多一次 |
| 仅一次 | `@once:2026-10-01 09:00` | 走 `DateTrigger`，跑完自动停用 |

### 19.2 「每天多次」两种填法

- **指定时间点**：chip 列表，默认 4 个、上限 **12 个**；新增默认值 =「上一个 +6 小时」，
  避免连点都在同一时刻；只剩 1 个时删除按钮禁用（按钮层 + 函数层双守卫）。
- **固定间隔**：选 1/2/3/4/6/8/12 小时 + 起始时间。
  起始时间会**把整点序列整体平移**（"从 8 点开始每 6 小时" → `0 2,8,14,20 * * *`），
  不是简单从 8 点起累加。
- 两种填法下方都有**实时回显**（「0:00、6:00、12:00、18:00 各执行一次」），
  保存前即可确认自己排的是什么。

### 19.3 ⚠️ 间隔下限（安全约束，不是 UX 偏好）

定时采集是周期性请求平台接口，**跑太密会触发风控把账号打废**。故：

| 相邻间隔 | 行为 | 视觉 |
|---|---|---|
| **< 60 分钟** | **拒绝保存**（前后端双拦） | `--dh-danger` toast |
| 60 ~ 120 分钟 | 只提醒，不拦 | `--dh-warning`（`is-warn`），**不用错误色** |
| ≥ 120 分钟 | 无提示 | `--dh-text-secondary` |

- 前端算最小间隔时**必须含跨零点回绕**：23:30 与 00:15 算 **45 分钟**，不是"跨天就不算"。
- 后端独立复算一遍，防止绕过界面直接打 API。
- 「日」或「周」字段有限制（每周一 / 每月 1 号）时一天最多跑一次 → **跳过判断**。

### 19.4 编辑回填

多时段表达式必须能**还原**成时间点 chip（`0 2,8,14,20 * * *` → 4 个时间输入），
否则用户改一次计划就把原排期冲掉。回填判定：`日 == * 且 周 == *`，
且时或分字段含 `,` `/` `-` `*` 之一。
