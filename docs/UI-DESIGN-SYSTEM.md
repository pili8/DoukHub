## 1. 核心原则

| 原则 | 说明 |
|------|------|
| **全 token 化，禁止硬编码颜色** | 所有颜色一律用 `var(--dh-*)`，不得写死色值（硬编码会导致深浅主题不跟随、多页不统一，历史教训：日志框 `#1a1c1e` 硬编码） |
| **深浅主题自动跟随** | 项目有完整暗色模式（`data-theme` 切换 + localStorage 记忆 + 跟随系统），用 token 即自动适配，零额外代码 |
| **风格统一优先** | 新组件先对齐项目已有范式（按钮 6px 圆角、卡片白底细边框、胶囊容器），不引入跳色 |
| **自用工具，精简文字** | 说明文字只留必要提示，删冗长解释 |
| **层次用填充强度表达** | 主次用 Filled / Tonal / Ghost 或浅深两档蓝，不用不同色相跳色 |

## 2. 主题机制

- 控制方式：`<html data-theme="light|dark">`（`style.css` 中 `:root` 与 `:root[data-theme="dark"]` 分别定义全部 token）
- 切换逻辑：`base.html` 内联脚本——`localStorage` 记忆用户选择，无记忆时跟随系统 `prefers-color-scheme`
- **规则：写样式永远引用 `var(--dh-*)`，让主题自动切换生效**

## 5. 语义色（状态 / 进度场景）

| 语义 | Token | 浅色 | 深色 | 用途 |
|------|-------|------|------|------|
| 进行中 / 信息 | `--dh-accent` | 蓝 | 亮蓝 | 日志 info、进度条、计数卡"总数" |
| 成功 | `--dh-success` | 绿 | 亮绿 | 日志 ok、分段条完成段、计数卡"成功" |
| 失败 | `--dh-danger` | 红 | 亮红 | 日志 err、分段条失败段、计数卡"失败" |
| 警告 | `--dh-warning` | 橙 | 亮黄 | 日志 warn、警告提示 |

**统一约定：进度 / 状态场景下，蓝=进行中、绿=成功、红=失败、橙=警告，全项目一致。**

| 折叠交互 | 折叠头 + chevron（旋转 90° 表示展开）；用于：下载设置、低频资产组、下载历史、模板弹层 |

## 7. 布局与间距

- 基准间距 16px；卡片内边距 20px；卡内区块间距 16px
- 单作品采集页固定四卡片结构：**作品链接 → 进度 → 资产结果 → 下载历史**
- 输入框操作按钮（粘贴 / 清空）悬浮于右下角，不占独立行
- 资产列表行高紧凑（缩略图 40px），超出限高滚动

## 8. 交互惯例

- **输入即反馈**：链接输入后即时预检，统计条一行汇总（数量 · 匹配数 · 平台计数），无效链接可点击定位
- **模式并列**：同一位置三按钮表示三种模式（解析 / 一键下载 / API），按钮动作 + 设置项联动
- **低频内容折叠**：音乐 / 封面等低频资产收进折叠组，默认收起只占一行
- **进度流式展示**：分段彩色进度条（完成=绿 / 进行中=蓝 / 失败=红 / 未到=灰）+ 当前消息 + 计数卡 + 日志行；解析=2 段、下载=3 段
- **下载方式**：本地 / 浏览器选择放在下载动作时弹出（不放在设置里）
- **ESC 关闭一切浮层**（2026-09-17）：确认框、任务面板、目录选择器、批量详情、移动端抽屉导航，
  键盘 ESC 均可关闭。多浮层叠加时**只关最上层**——后注册的处理器须用捕获阶段
  （`addEventListener('keydown', fn, true)`）先读 `document.querySelector('.dh-show')`，
  发现上层浮层存在就放行，避免一次 ESC 把弹窗和抽屉一起关掉。

## 10. 设置页结构（2026-08-21 定稿）

> 「整体设置页面」采用**分组 Tab + 折叠卡**，不做长滚动页。本节为结构决策记录。

### 10.1 分组 Tab 导航

- 顶部**分组 Tab**（DoukHub配置 / 下载与文件 / 内核服务 / 功能配置），点击切换面板（`.settings-group.active` 显隐），**不再滚动长页**。
- 组内仍可折叠卡（`.settings-card.open`）。
- 保留 `scrollToGroup` 兼容旧入口；支持 URL hash 直达分组（`#group-download`），供采集页「管理模板」等外部跳转。
- 深色主题 / 交互惯例沿用全 token 规范。

### 10.2 下载与文件分组结构

| 卡片 | 内容 |
|------|------|
| **保存方案** | 双卡横排：**增量采集**（按账号归档，根目录+平台/账号自动层级） / **单作品采集**（直存，默认目录留空则用增量根目录）；各卡含「编辑命名」直达统一编辑器 |
| **文件命名规则** | 统一命名编辑器：增量模板 / 单作品模板 小胶囊切换；字段**拉平** |
| **下载内容选项** | 增量附属下载（音乐/封面/大小上限/导出格式）；单作品附带下载在采集页「一键下载」设置 |

### 10.3 命名统一（字段拉平）

两套引擎字段**在 UI 层合并为同一套**，保存时按方案映射回引擎字段：

| UI 字段 | 增量引擎键 | 单作品引擎键 |
|---------|-----------|-------------|
| 发布时间 | `create_time` | `create_time` |
| 作品类型 | `type` | `type` |
| 作者 | `nickname` | `author` |
| 标题 | `desc` | `title` |
| 作品ID | `id` | `id` |
| 账号UID | `uid` | —（仅增量，角标） |
| 账号标识 | `mark` | —（仅增量，角标） |
| 平台 | —（仅单作品，角标） | `platform` |

- 编辑器同一套 chips，非当前方案可用字段自动隐藏，专属字段带「仅增量 / 仅单作品」角标。
- 单作品模板支持多模板 + 默认模板 + 「复制为增量」；字段编辑自动同步回当前模板并防抖持久化。
- **兼容性**：只改了前端 UI 与映射，后端 API（`/api/collection/defaults` 存 `name_format`、`/api/collection/single-work/preferences` 存 `{author}/{title}`）未变，存量配置零迁移。

### 10.4 共享命名工作台（2026-08-21 晚定稿 v6 → 落地）

> 用户批准 v6 布局原型，落地后的真实结构：**卡片内不再有命名编辑器**，统一收进**底部滑出式共享命名工作台**（单一 DOM 实例）。

#### 10.4.1 卡片区（两大组：单作品采集 / 增量采集）

| 组 | 内容 |
|----|------|
| 单作品采集 | 「保存目录」分区（方案目录 + 浏览，留空用增量根目录）+「命名」分区（**摘要行** + 「编辑模板」按钮，紫色强调） |
| 增量采集 | 「下载目录」分区（根目录 + 浏览 + 平台/账号目录树）+「命名」分区（摘要行 + 编辑模板，绿色强调）+「附属下载」分区（2 行格：第 1 行 音乐/动态封面/静态封面 开关；第 2 行 **文件大小上限在前**、**数据导出格式在后**） |

- 摘要行实时显示字段示例 + `.mp4`，字段顺序改动即时同步；「每作品独立子文件夹」开关已从批量卡移入工作台。

#### 10.4.2 底部共享命名工作台（`.workbench`，单一 DOM 实例）

- 触发：任一卡片「编辑模板」→ `openWorkbench('single'|'batch')`；遮罩点击 / 关闭按钮收起。
- 结构自上而下：
  1. **作用域胶囊**（单作品 / 增量）：`wbScope(s)` 切换，读写各自独立的 `tplState[scope].parts`；
  2. **模板管理条**（`#wb-tpl-sel`）：单作品=方案下拉（含默认标记）+ 新建 / 重命名 / ★设默认 / 删除 / 「设为增量默认」（`dupToBatch`，复制后自动切到增量作用域展示结果）；增量=固定「增量默认模板」占位（引擎级，无多方案）；
  3. **字段池**（`#wb-pool`）：chips 点击加入/移除命名，专属字段带「仅增量 / 仅单作品」角标；
  4. **排序带**（`#wb-belt`）：已选字段拖动换位、✕ 移除；
  5. **存储**（仅增量作用域显示）：「每作品独立子文件夹」开关（唯一保留的引擎级选项，`folder_mode`）；
  6. **预览**（`#wb-pv`）：文件名实时示例（分隔符 `-` 已固化）。
- JS 契约：`renderTplEditor(scope)` 幂等（摘要常驻 + 面板只渲染当前作用域）；`templateDragStart(event, scope, index)` 拖动签名修正了旧版参数错位；保存映射与 §10.3 一致，后端 API 未变。

## 11. 全局视觉标准 v2 —— 三层表面 + 蓝色强调（2026-09-05 草案，待确认）

> 本节将 §1-6 的令牌规范升级为**全站页面的强制标准**：所有页面（含表浏览、数据概览、备份、同步各页）新增/改动 UI 时逐条对照。
> 依据：v2.2.6（表浏览筛选面板）、v2.2.7（全局界面统一）两轮落地实践沉淀，已核对与 style.css / 各模板实现一致。

### 11.1 三层表面体系（空间层级，全站唯一的空间语言）

| 层级 | Token | 浅色值 | 角色 | 视觉感受 |
|------|-------|--------|------|---------|
| L0 页面背景 | `--dh-background` | `#FBFAF7` 暖白 | 最底层画布 | 平铺 |
| L1 卡片表面 | `--dh-surface` | `#FFFFFF` | 卡片 / 面板 / 弹窗 | 浮起（靠 1px 边框 + 阴影区分） |
| L2 降级面 | `--dh-surface-muted` | `#F5F2EC` 米色 | 日志、输入区、胶囊底、次级信息 | 凹下去、退后 |

**米色的正名**：米色是**降级面**，不是"着重面"。它的本职是让白卡浮起来、让次要内容沉下去。真正的"着重"是蓝色（实心按钮 + accent-soft 选中态）。

红线：
1. 一层卡片内**只套一层米色**（米色套米色会糊成一团）；
2. 米色块对比极弱，必须靠边框或内容自身站住，不能单独承担分区；
3. 弹窗、面板一律用 L1 白底，不得用米色打底。

### 11.2 蓝色强调的唯一性

| 强度 | 样式 | 用途 |
|------|------|------|
| 最强 | 实心蓝 `--dh-accent` 白字 | **主操作**，一屏内只允许一个 |
| 次强 | `--dh-accent-soft` 浅蓝底 + 蓝深字（tonal / halo） | 选中态、筛选高亮、次级主打项 |
| 中 | 白底 + 1px 边框描边（`.btn-secondary`） | 次要操作 |
| 弱 | ghost 灰字虚线框 | 仅展示型入口 |

- **选中态 halo 模式**：`accent-soft` 底 + `--dh-accent` 深字（+ 可选 1px 蓝边），用于筛选按钮选中、Tab 激活、列菜单选中项。
- 一屏内蓝色实心按钮 > 1 个即视为违规；"一屏"指视口内同批操作区。

### 11.3 文字与对比度红线

- 三档文字：`--dh-text`（正文）/ `--dh-text-secondary`（次级）/ `--dh-text-muted`（弱化）。
- `--dh-text-muted`（`#9C9387`，对白底约 **2.7:1**）**只允许用于辅助小字**（时间戳、计数、占位符），禁止承载正文——正文 AA 要求 4.5:1。
- 实心蓝按钮白字约 6.3:1，达标；深色模式下语义色自动提亮，无需逐页适配。

### 11.4 状态与语义色（全站唯一约定）

**语义约定：蓝 = 进行中/信息，绿 = 成功，红 = 失败，橙 = 警告。** 进度条分段、计数卡、日志行、状态徽章全部遵守，不得换色相。

| 场景 | 规范 |
|------|------|
| 表浏览状态胶囊 | halo 浅底 + 深字（沿用）：待解析=灰、已就绪=蓝、已生成=绿、已删除=橙、解析失败=红 |
| 任务/历史状态 | 一律映射 `--dh-warning / --dh-accent / --dh-success / --dh-danger` 语义令牌，禁止 JS 里写死 hex |
| 日志行 | `.log-ok / .log-err / .log-info / .log-warn` 四类 |

- **页局部补充色模式**（如设置页紫色）：在该页 `<style>` 顶部定义 `--dh-purple / --dh-purple-soft` 两枚页局部令牌（明暗各一档），页面内只引用令牌；全局 `style.css` 不为其扩表。

### 11.5 复用组件规范（v2.2.6 / v2.2.7 已落地，新页面直接套用）

| 组件 | 类名 | 规范要点 |
|------|------|---------|
| 日志面板 | `.log-panel` / `.workflow-log` | L2 米色底 + 等宽字体 + 语义色行；**禁止深色黑底**（"终端感"靠等宽字体与语义色行表达，不靠黑底） |
| 空状态 | `.empty-state` | 三段式：`es-title`（14px/600）+ `es-desc`（12px muted，可省）+ `es-action`（主/次按钮，可省）；小容器加 compact 变体；图标居中 |
| 区块卡头 | `.card h3` | 图标 chip 化：accent-soft 圆角小底 + accent 图标 + 标题，右侧留动作区；全局统一，不再各页自定义 |
| 指标卡 | `.db-stats-enhanced .stats-card` | 左侧语义色竖条（`--sc-color` 注入）+ 大数字（tabular-nums）+ 次级说明；悬停轻微浮起 |
| 全局进度浮条 | `.global-progress-chip` | 胶囊造型 + 呼吸图标 + 细进度条；暂停态加 `.is-paused`（图标转警告黄、停止呼吸） |
| 折叠卡 | `.settings-card` | chevron 旋转 90° + 高度过渡动画；展开态才显示 `.open` |
| 筛选弹窗 | `.tbl-filter-popup` | L1 白底 + 分组小标题（排序 / 筛选值）+ 头部分隔线 + 检索内嵌清空按钮 + 底部主按钮加宽加粗 |

### 11.6 硬编码禁令与新页面自检清单

**禁令**：模板与 JS 中禁止出现任何 hex / rgb() 色值，唯一例外是令牌定义处（`:root` 块、页局部补充色声明行）。

新页面 / 改版自检清单（逐条打勾才算完成）：
1. [ ] 颜色全部 `var(--dh-*)`，无硬编码（可 `grep -nE '#[0-9a-fA-F]{3,8}'` 自查）；
2. [ ] 层级正确：背景 L0 → 卡片 L1 → 降级区 L2，米色只套一层；
3. [ ] 实心蓝按钮全屏 ≤ 1 个；选中态用 accent-soft halo；
4. [ ] 状态/进度色遵守"蓝进行绿成功红失败橙警告"；
5. [ ] 弱化文字未承载正文；
6. [ ] 空状态、日志、卡头、指标卡使用 §11.5 统一组件，不另起炉灶；
7. [ ] 深色模式无需单独适配（引令牌即自动跟随），改完明暗各切一遍目检。

## 12. 深色模式与对比度硬约束（2026-09-17 全站审计沉淀，强制）

> 依据：v2.2.8 全站界面审计（16 路由 × 明暗双主题共 32 次实测）。
> 以下缺陷**只在渲染态暴露**，静态搜色值是查不出来的 —— 新增/改版后必须实测深色。

### 12.1 表单控件必须显式或继承文字色

`button / input / select / textarea` 的 `color` 默认取浏览器系统色（ButtonText / FieldText，**恒为黑**），
**不继承父级**。只写背景、不写文字色的按钮，浅色下看似正常，深色下就是黑字压暗底（实测 1.24:1，近乎不可见）。

- 全局已在 `style.css` 兜底：`button, input, select, textarea { color: inherit; }`
- 组件类若自定义背景色，**必须同时给出 color**，不得只设 `background`。

### 12.2 "实心强调面上的前景色"唯一走 `--text-on-accent`

任何 `background: var(--dh-accent)` / `var(--accent-active)` 的实心面，其文字、图标、左侧指示条颜色
一律用 `var(--text-on-accent)`（= `--md-on-primary`），深浅主题各得 6.3:1 / 8:1。
**禁止硬编码 `#fff`** —— 深色模式亮蓝底上白字只有 2.2:1。

### 12.3 语义色用于文字时的对比度

| 令牌 | 浅色值 | 对白底 | 结论 |
|------|--------|--------|------|
| `--dh-accent` | `#0061A4` | 6.3:1 | ✅ 可直接作文字 |
| `--dh-danger` | `#C2410C` | 5.0:1 | ✅ |
| `--dh-warning` | `#B45309` | 4.5:1 | ✅ 临界可用 |
| `--dh-success` | `#15803D` | 4.6:1 | ✅（原 `#16A34A` 仅 3.16:1，已调深） |

- 语义色作**文字**必须 ≥ 4.5:1；作**图形 / 边框 / 进度条** ≥ 3:1 即可。
- 大数字、关键指标**不得用 `--dh-text-muted`**（2.4~2.7:1），它只服务时间戳 / 计数 / 占位等辅助小字。

### 12.4 操作列按钮一律降级

表格 / 列表**每行重复出现的操作按钮**（重试、详情、编辑）用 `.btn-secondary`（描边）或图标按钮，
**禁止 `.btn-primary`** —— 一屏 10+ 个实心蓝会淹没页面主操作。实心蓝只留给当前视图的主操作。

### 12.5 审计口径（可复用）

实测五项：① 实心强调元素计数（一屏 ≤1，导航 / tab 激活不计）；② 文字对比度 < 4.5:1 清单（fs ≥ 12px）；
③ 控制台错误；④ `scrollWidth > innerWidth` 横向溢出；⑤ 深色下是否存在 `rgb(0,0,0)` 文本。

## 13. 表单控件统一基线（2026-09-17 控件审计沉淀，强制）

### 13.1 铁律：控件必须命中已定义的样式

**任何"看起来像输入框 / 下拉 / 文本域"的元素，都必须命中 `.form-group input|select|textarea` 或 `.input` 之一。
禁止只写 class 名而不落样式。**

历史教训：全站 4 处 `class="input"` 在 CSS 中没有任何定义，一直掉到浏览器默认样式
（`2px rgb(118,118,118)` 边框 + 直角 + 仅 **19px 高**），高度只有旁边控件的一半 ——
这类"半截高、粗灰边、直角"的控件是风格不统一最刺眼的来源，且**浅色下不易察觉**。

### 13.2 统一参数（不得逐页另立）

| 属性 | 值 | 说明 |
|---|---|---|
| 高度 | `min-height: 34px` | 与 `.btn`(34px) 严格等高，并排不错位 |
| 圆角 | `var(--dh-radius-sm)` = 6px | 与 `.btn` / `.path-pill` 同族 |
| 边框 | `1px solid var(--dh-border)` | hover → `--dh-border-strong`（**不得**用近黑的强调色，过重） |
| 焦点环 | `0 0 0 3px var(--dh-accent-soft)` | 键盘可见性 |
| 字号 | 13px（窄屏 15px） | 与正文一致 |
| 禁用 | `--dh-surface-muted` 底 + `--dh-text-muted` 字 | |

### 13.3 路径 / 目录字段三件套

- **`.path-pill`（只读路径胶囊）**：柔和底 + 强调色图标 + 等宽路径（超长省略、`title` 悬停看全）+ 右侧柔和图标按钮。
  用于"当前目录"展示，**禁止**用灰底贴边 mono 文字或裸文字行。
- **`.field-affix`（输入框内嵌按钮）**：输入框与"选择文件夹"按钮合成一个控件（按钮内嵌右端），
  **禁止**在输入框旁挂竖排按钮列。
- **`.field-actions`**：操作按钮右对齐横排；**`.field-group + .field-group`** 用**虚线**分隔同卡片内的次级分组。
- 配套：`.field-label`（字段标签）、`.field-hint`（提示小字）、`.icon-btn-soft`（柔和图标按钮）。

### 13.4 裸奔控件扫描（可复用口径）

用 Playwright 遍历全站**可见**的 `input / select / textarea`，按 computed style 分组；凡同时命中
`border-width: 2px` + `border-radius: 0` + `border-color: rgb(118,118,118)` 的，即为掉到浏览器默认样式的控件。

> ⚠️ **静态扫描（只比对 class 名）会误判**：属性选择器命中的控件（如 `.ext-pill input[type="checkbox"]`）
> 在 class 扫描里表现为"无定义"，实际已有样式。判定口径**必须以浏览器实测为准**。

### 13.5 勾选框 / 单选框

```css
:where(input[type="checkbox"], input[type="radio"]) { accent-color: var(--dh-accent); }
```
`:where()` 特异性为 0，AG Grid 等自带主题仍可覆盖，不会误伤第三方组件。

### 13.6 已知遗留（待决策，勿在未讨论前动手）

- **select 原生箭头**：统一需 `appearance:none` + 自定义箭头，但各页 select 已有各自
  `background` 简写声明（含 ID 选择器）会覆盖之，收益不抵风险。
- **双图标库并存**：项目同时加载 lucide 与 Phosphor，9 个模板共 117 处 `ph ph-*`，
  两套线宽/比例有细微差异。统一需成批替换 + 图标名映射，属独立课题。**（2026-09-17 用户决定：不做）**

## 14. 统计数值的颜色语义（2026-09-17 沉淀，强制）

### 14.1 分类计数禁用语义色

统计条里的数字分两类，**颜色待遇必须区分**：

| 类型 | 例 | 用色 |
|---|---|---|
| **主指标**（本次任务的总量） | 可采 / 账号总数 | `--dh-accent`（蓝色文字，非实心） |
| **分类计数**（把主指标拆开的明细） | 首次 / 增量 / 待处理 | `--dh-text`（正文色） |
| **弱化计数**（本轮不处理的部分） | 跳过 | `--dh-text-secondary` |
| **真正的状态结果** | 成功 / 失败 | `--dh-success` / `--dh-danger` 保持不变 |

原因：`橙=警告、绿=成功` 是状态语义。用橙色表示"首次"、绿色表示"增量"，
用户会把"分类"读成"状态"，是典型的语义撞车。**只有"成功/失败"这类结果才配用语义色。**

> 一屏统计条里 `--dh-accent` 只给主指标一个，其余中性化 —— 与 §11.2「蓝色强调的唯一性」同源。

### 14.2 大数字不得使用 `--dh-text-muted`

`--dh-text-muted`（浅色 `#A39E96`）**只服务时间戳 / 占位符这类 ≤12px 辅助小字**（约 2.4:1）。

统计条数字是 **20px / 700**，按 WCAG 属"大字号"，**下限是 3:1**；浅色底上它只有 **2.38:1**，
连大字号线都不到。需要弱化外观时用 `--dh-text-secondary`（浅色 6.5:1 / 深色 9.4:1）。

**判定口径**：任何数字/文字元素，先按字号算门槛（≥18.66px 或 ≥24px 取 3:1，否则 4.5:1），
再决定能否用弱化色 —— 不要因为"它看起来是次要信息"就套 `--dh-text-muted`。

## 15. 移动端适配基线（2026-09-17 沉淀，强制）

> 本轮首次把视口压到 375 / 768px 实测（此前所有审计都在 1440px 做）。
> **"没有横向滚动"≠"可用"** —— 下面的缺陷里，前两条在 `scrollWidth > innerWidth`
> 这个检查项下**全部为 0**，是靠量几何和看渲染才发现的。

### 15.1 内容首行必须避开固定定位的汉堡按钮

汉堡按钮是 `position: fixed` 的 **(12, 12, 44×44)**，而 `.main` 的首行内容也从 (12,12) 开始
→ **两者完全重叠**，每个页面的标题首字都被压住；副标题更长时被挤成断词换行。

**强制做法**：≤768px 下给页头标题容器 `padding-left: 56px` + `min-height: 44px` +
`justify-content: center`，与汉堡同处一行。**只缩标题容器，不缩整块 header**
（否则操作按钮行也会被左移，白白浪费 56px 宽度）。

需覆盖的两种页头写法：

| 写法 | 选择器 |
|---|---|
| `.page-header` + 直挂 `h2` | `.page-header > h2` |
| `.page-header` + `.page-title-wrap` 包裹 | `.page-header > .page-title-wrap` |
| `.page-head` + `.page-title`/`.page-sub` | `.page-head > div:first-child` |

**新增页头时必须沿用这两种结构之一**，否则拿不到让位规则。

### 15.2 媒体查询断点

| 断点 | 用途 |
|---|---|
| ≤768px | 移动端主断点（抽屉导航、堆叠页头、触控目标、字号下限） |
| ≤420px | 极窄屏（仅缩小数字字号，**不得再降标签字号**） |

**页面级修正一律写进 `@media (max-width: 768px)`，桌面值一个都不改。**

### 15.3 移动端字号下限

- **正文与数据（表格 td、表单值）≥12px**，不得为"塞下更多列"降到 11px 以下。
- **标签/徽章类辅助小字 ≥11px**，且**绝不允许在 ≤420px 再降一档**（曾出现 9px）。

⚠️ **实现注意**：各模板自己的 `<style>` 在文档顺序上位于 `style.css` **之后**，
同优先级会覆盖全局规则。所以**组件的字号修正必须写在定义它的那个模板里**，
写进 `style.css` 会被静默吃掉。

### 15.4 触控目标

- 常用按钮/tab ≥ **36px** 高（实测曾出现 29px 的 tab、20px 的"全不选"）。
- 卡片内的搜索/筛选输入框 ≥ **36px**；**AG Grid 内联编辑器除外**（改它会撑高表格行高）。
- 触控修正**不得牵动表格行高**，因此禁止用通配选择器批量设 `min-height`。

### 15.5 卡片式表格（窄屏把表格行改成卡片）

窄屏卡片的常见做法是把卡片塞进 `<tr><td colspan="N">`，此时**表格宽度仍由桌面表头决定**，
卡片会被撑到远超声宽并被裁切（实测 533px vs 视口 375）。

**强制三件套**：

```css
#该表格 { table-layout: fixed; width: 100%; }
#该表格 thead { display: none; }          /* 卡片自带字段标签，表头无意义 */
.卡片体 { grid-template-columns: minmax(0, 1fr) minmax(0, 1fr); }  /* 不能用 1fr */
```

`1fr` 的隐含下限是 `min-content`，长值会把列撑爆 → **网格里放可变长文本一律用 `minmax(0, 1fr)`**。

### 15.6 移动端审计口径（在 §12.5 五项之外追加）

⑥ 标题文字左边界 vs 汉堡右边界（用 `Range.getClientRects()` 量**文字**，
`getBoundingClientRect()` 量的是边框盒，会被 `padding-left` 骗过）；
⑦ 375px 下 `<12px` 的文字清单（区分"正文数据"与"徽章标签"）；
⑧ 卡片宽度 vs 视口宽度（卡片式表格必查）；
⑨ 触控目标高度分布（<36px 清单，排除表格内行内按钮与内联编辑器）；
⑩ 页头副标题是否被挤成单字换行。
